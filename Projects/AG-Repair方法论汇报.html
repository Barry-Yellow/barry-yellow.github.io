1问题定义与动机

为什么不能全量重跑？

传统方法：失败点之后全量重跑，浪费大量计算
AG-Repair：只修复根因 + 被污染节点，保留干净节点
目标：正确性 · 最小干预 · 最大复用 · 一致性

3根因定位

找最早、最关键、最值得修的节点

硬信号优先：异常 / 工具失败 / 协议违规 / verifier 失败
评分公式：S_root = α·A(v) + β·I(v) + γ·D(v) + δ·R(v)
策略：首选单根因 → 失败后升级多根因联合修复

4影响边界识别

区分 Clean / Partial / Invalid，精确划定修复范围

污染传播：P(v) = maxu∈Pred(v) P(u) · w(u,v) · λ(0.85)，沿强依赖边扩散
复用评分：S_reuse = 0.5·S_correct + 0.3·(1−P) + 0.2·S_compat
升级策略：分支 Invalid 占比 > 40% 或含高层 planning 错误 → 整体 REWRITE_BRANCH
Clean
Sreuse ≥ 80
完全可复用 → 保留
Partial
60 ≤ Sreuse < 80
部分可复用 → 局部修补
Invalid
Sreuse < 60
不可复用 → 重放或重写

∑ 三层核心创新

1. 错误边界识别

把错误传播范围从经验判断变成图上的量化问题 — MAICG 污染传播模型 + 复用评分，精确区分 Clean / Partial / Invalid

2. 修复建议生成

把开放式"怎么修"变成受限动作空间中的成本感知决策 — 六种动作按代价梯度排列，层层升级，可解释可审计

3. 增量重执行

把"从错误点之后全部重来"变成"从最近安全状态出发，仅重放必要子图" — 依赖 checkpoint + journal replay + Active Dependency Frontier

AG-Repair 不只是 failure attribution 框架

而是一套真正面向 failure recovery 的完整方法论
