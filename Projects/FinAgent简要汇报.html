3Agentic RAG & 三层记忆

混合检索 + RRF 融合 · 分层记忆管理

Agentic RAG：Agent 自主决策检索策略，不足时重检索，而非静态 Pipeline
RRF 融合：score(d) = Σ 1/(k+rank)，兼顾语义相关性与关键词精确匹配
三层记忆优先级：短期 > 长期 > RAG，高优先级覆盖低优先级

Agentic RAG Pipeline

Q 查询理解 — LLM 改写 + 实体提取
R1 向量检索 — ChromaDB 语义匹配
R2 BM25 检索 — 关键词精确匹配
F RRF 融合 — 合并两路排名结果
G LLM 生成 — 评估相关性，不足重检索

5金融 Agent 的三条硬约束

低幻觉 · 低容错 · 强解释：金融分析不是普通问答

数字不能猜：核心数值必须绑定来源，并通过工具计算和规则校验
冲突不能硬判：结论要经过置信度门控，低置信时主动降级
判断必须可复核：输出因果链、证据链和关键假设

1. 数值幻觉零容忍

问题

金融 Agent 不能“看起来合理地报数”：价格、同比、估值倍数、财报字段一旦报错，后续分析会整体失真。

原因

金融数据强依赖时间、口径和单位；LLM 容易补全缺失值，但金融场景不允许把“合理猜测”当事实。

具体方案

核心数字绑定来源、时间戳、字段名、单位；价格/同比/估值/财务指标由工具计算；输出前做交易日/报告期一致性、元/万元/亿元单位、百分比/小数、会计等式和异常波动阈值校验，失败则只返回“数据不足/需复核”。

2. 置信度门控 + 失败降级

问题

多来源冲突、字段缺失或数据过期时，普通 Agent 仍可能给出确定性判断；在金融场景，“继续回答”比“暂不下结论”更危险。

原因

金融结论往往依赖多源证据链，一处冲突就可能改变方向；错误代价不是体验下降，而是资金损失和合规风险。

具体方案

按来源数量、来源一致性、数据新鲜度、字段完整性、关键指标校验结果计算置信度；高置信输出判断，中置信输出倾向并标注冲突点，低置信禁止强判断，降级为事实汇总 + 人工复核提示。

3. 因果链可解释输出

问题

只给“利好/利空/看多/看空”没有复核价值，用户需要知道判断从哪里来、经过了哪些变量传导。

原因

金融分析很容易把相关性误当因果性；报告型输出必须能被审阅、追责和复盘。

具体方案

固定生成链路：事件/触发因素 → 影响变量 → 财务指标变化 → 估值/风险传导 → 最终判断。每一步都挂载数据点、来源片段、计算过程、前提假设，并补充反事实或风险提示；缺任一关键证据时，结论自动降级为“可能影响路径”。

∑ 四大核心创新

1. 意图驱动路由

两阶段识别（关键词预筛 + LLM 精分类）+ 5 种意图自动分发，多意图按依赖关系串行执行，结构化 JSON 约束保证格式稳定性

2. Agentic RAG

混合检索（向量 + BM25）+ RRF 融合，Agent 自主评估检索质量并决策是否重检索，相比传统 RAG 显著提升召回准确率

3. 三层记忆管理

短期（内存 TTL）· 长期（JSON FIFO）· RAG（向量语义）分层管理，优先级策略解决跨层信息冲突，LFU+FIFO 混合淘汰

4. 金融可信分析闭环

来源绑定 + 工具计算 + 规则校验控制数值幻觉，置信度门控处理冲突数据，因果链与证据链保证结论可复核
