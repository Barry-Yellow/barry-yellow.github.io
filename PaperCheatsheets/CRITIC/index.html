CRITIC

让大模型通过工具交互式批评来修正输出

CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing

Zhibin Gou · Zhihong Shao · Yeyun Gong · Yelong Shen · Yujiu Yang · Nan Duan · Weizhu Chen
清华大学 / Microsoft Research Asia / Microsoft Azure AI
ICLR 2024 · 首发 2023-05-19 · 阅读版本 v4：2024-02-21

一句话：同一个冻结的 LLM 先给初稿；核查时调用搜索、Python 或毒性 API，把返回信息接入批评文本，再据此改稿，反复到停止条件触发。

最吸引人的点：“改几遍”不是关键，反馈有没有带来模型自身不知道的新信息才是。工具让批评有外部依据，但没有把批评变成正确性证明。

① Input / Output：输入问题或文本前缀，LLM 先靠参数知识生成答案、程序或续写。

② Verify / External Tools：LLM 提出查询或代码；工具返回网页片段、执行状态/值、分类分数。一次核查可以多次交互。

③ Critiques：把工具返回接在调用之后，LLM 解释哪里有问题、证据支持什么、应该怎样改。

④ Correct：把原问题、当前稿与批评一起给 LLM，生成下一稿。蓝色箭头是信息与控制流程，不表示梯度更新。

来源：§3，图 1，算法 1，PDF pp.2、4–5。

以前哪里容易失败 → 本文补上什么

  • 只靠 LLM 自己判断：同一模型可能重复原来的知识错误，还会把正确答案改错。→ 核查阶段引入外部反馈，减少纯粹自圆其说。
  • 只有分数或“错了”：难指明下一稿该改哪。→ 让 LLM 将观察转成自然语言批评，包含错误位置、依据与修改建议。
  • 专门训练纠错器：额外数据和训练会增加接入成本。→ 用少量任务示范教会核查/改写，测试时循环，不额外更新模型权重。

真正新增的东西

统一接口：把不同工具包装成“文本输入 → 文本返回”，同一核查—修正套路覆盖事实、程序与安全属性。

证据参与改写：反馈不只筛掉坏样本，也进入下一次生成，告诉模型怎样避免同类错误。

系统性验证：用去工具消融、正常/Oracle 设置区分“能改错”与“知道何时该改”。§1、§3–4，附录 C。

实现边界要记住

论文实验按任务预先指定工具；自动选工具只是 §3.3 讨论的可行扩展。模型是黑盒、冻结的；这是输出修正框架，不是多 Agent 故障定位、系统回滚或训练算法。

算法 1 翻成可执行的 4 步

1 · 初稿 ŷ₀

输入 x + 少量示范提示 ℘ → LLM 生成初稿。

2 · 核查 cᵢ

x + 当前稿 ŷᵢ → 调工具 → 返回与模型解释组成批评。

3 · 改写 ŷᵢ₊₁

x + ŷᵢ + cᵢ → LLM 重新生成；没有参数训练。

4 · 停止 / 再核查

批评判定正确、达到轮数或任务反馈触发停止；否则回到 2。

ŷ₀ ∼ PM(· | ℘ ⊕ x)　　cᵢ ∼ PM(· | ℘ ⊕ x ⊕ ŷᵢ, T)　　ŷᵢ₊₁ ∼ PM(· | ℘ ⊕ x ⊕ ŷᵢ ⊕ cᵢ)

⊕ 是文本拼接；T 是外部工具集合。cᵢ 是工具交互与 LLM 分析形成的上下文，不是人工金标准。通用算法与各任务实际停止规则略有不同，见第 3 页。

中文阅读顺序：查证一个“人名”

  1. 问题：谁与一位出生于 1995-04-29 的俄罗斯冰舞选手搭档，赢得 2016 俄锦赛银牌？
  2. 初稿：模型答 Ivan Bukin，并把搭档、生日、比赛年份连成一个故事。
  3. 先查合理性：问题要人名，输出也是人名，格式合格；这一步没有验证事实。
  4. 再查真实性：先搜索初稿中的获奖说法，返回的是 2012 青年组线索，不支持所问年份；随后按问题查 Wikipedia，找到 Victoria Sinitsina 的生日线索。
  5. 补第二跳：用 Sinitsina + 2016 银牌搜索，返回其与 Nikita Katsalapov 的搭档/奖牌信息。
  6. 批评 → 改稿：模型整合上述返回，指出初稿人物不符，再生成 Katsalapov 的答案。
工具没有直接认证整段答案。检索到另一年份并不能单独证明原说法为假；这里靠后续人物与赛事线索补证。检索遗漏、网页错误和模型误读仍会留下错误。

工具带来的新信息

Execution：No runtime error
Output：answer = −4.0

解释器能说明“这个程序运行得到什么”，不能说明“程序是否表达了题意”。

中文阅读顺序：代码能跑也会错

  1. 题意：4 人各买一张切成 4 片的披萨；Bill/Dale 各吃 50%，Ann/Cate 各吃 75%；剩几片？
  2. 初稿 bug：总片数为 16；代码却对总量分别乘 50% 和 75%，得到 16 − 8 − 12 = −4。
  3. 执行反馈：没有异常，但输出为负。“No runtime error”与“答案对”是两件事。
  4. 批评：剩余片数应非负；逐句核对题意，发现比例应作用于每个人自己的 4 片，并计入两个人，而非整组总量。
  5. 改写：Ann/Cate 吃 4 × 0.75 × 2 = 6；Bill/Dale 吃 4 × 0.5 × 2 = 4；剩 16 − 6 − 4 = 6 片。
# 原例的修正版逻辑
pizza_pieces = 4
ann_cate = 4 * .75 * 2
bill_dale = 4 * .5 * 2
answer = 4*4 - ann_cate - bill_dale
# 6.0
语义检查仍靠 LLM。如果错误程序输出了看似合理的正数，解释器不一定提供明显的错误信号。

第三种反馈：毒性 API，不是事实检查器

检查对象：对生成的续写调用 Perspective API，得到整体毒性与 insult、profanity、identity attack 等细分属性分数。

进入批评：选择分数最高的属性，将其写成“文本在某属性的毒性分数为 X%”，作为下一轮非冒犯续写的反馈。

边界：这是分类器估计，不代表伤害的真实概率，也不能确认新闻事实、法律适当性或全部安全风险；模型要兼顾内容、流畅性与分数。

使用协议与证据边界

三任务用的是不同工具；停止规则不是“已经证明正确”

任务 / 初稿工具具体返回什么实际修正与停止设置验证不到什么
事实问答
CoT 初稿		Google 查询 → top-1 网页；按 snippet 模糊匹配提取最多 400 字符；最多交互 7 次。最多 3 轮；连续两次修正的答案不变时提前停；greedy 解码。网页真伪、证据是否覆盖全部主张、复杂推理仍需判断；片段可能不完整。
数学程序
PoT 生成 Python		解释器异常/超时等消息，以及程序执行后 answer 的值。最多 4 轮；连续两次修正执行结果不变时停；初稿 greedy，修正用 p=0.5 核采样防循环。没有金标准答案/完备测试；执行成功不保证题意建模、单位、遗漏条件正确。
降低毒性
给定前缀生成续写		Perspective API 的整体和细分属性分数；把最高分属性写成文本反馈。最多 4 轮；整体毒性分数 <10% 时停；核采样 p=0.9。低分不是全面安全证明，也不验证事实；指标受分类器偏差影响。

相邻思路：差异在反馈来源与使用位置

工作它在做什么 → CRITIC 的侧重
Self-Refine同一 LLM 生成反馈、改稿、迭代，无需额外训练。→ CRITIC 在核查时接入外部工具，避免反馈只来自模型自身。不据此断言所有任务均更优。
Reflexion把任务反馈转为反思，存入 episodic memory，指导后续尝试。→ CRITIC 聚焦当前输出的核查—改写循环。Reflexion 也可用外部反馈，不能笼统归为“无工具”。
ReAct在解题过程中交织推理与行动/检索。→ CRITIC 从已有初稿出发核查和改正，也可接在 ReAct 初稿后。
RARR为既有生成补找外部依据，并尽量保留原文地修订无支持内容。→ CRITIC 将反馈循环扩展到程序执行与毒性属性。

CRITIC §2、附录 C/Table 4；Self-Refine、Reflexion、ReAct、RARR 的介绍另核对其官方摘要。这里只比较机制，未复核它们的全套实验。

读完最该留下的判断

为什么有用：外部观察能打破模型的原有错误；自然语言批评把观察连接到具体修改，而非只告诉它“再试一次”。

为什么仍会失败：查不到或误读证据、运行结果语义不明、分类器偏差、LLM 判断错，都可能造成漏改或误改。答案稳定只说明收敛，不说明正确。

代价与范围：多轮 LLM/工具调用增加延迟；依赖人工示范与提示构造；只验证了文本任务与论文中的模型版本。没有证明适用于任意任务/模型。附录 A、D.2。

重要参考文献：按理解本篇的用途读

① Self-Refine: Iterative Refinement with Self-Feedback（Madaan et al., 2023）：最直接的“自反馈→改稿”参照，帮助分辨迭代本身与外部反馈的价值。

② Reflexion: Language Agents with Verbal Reinforcement Learning（Shinn et al., 2023）：反思存入记忆以改进后续 trial；理解跨尝试记忆与当前稿修正的区别。

③ ReAct: Synergizing Reasoning and Acting in Language Models（Yao et al., 2023）：交替推理与工具行动；CRITIC 采用其风格构造交互示范。

④ Program of Thoughts Prompting（Chen et al., 2022/2023）：用程序表达推理、让计算机算数；本篇数学任务的初稿基线。

⑤ RARR: Researching and Revising What Language Models Say, Using Language Models（Gao et al., 2022/2023）：后验检索与有依据的改写，理解事实核查这一支的前作。

⑥ RealToxicityPrompts（Gehman et al., 2020）：诱发毒性续写的评测集；本篇采样其非毒性前缀，并以分类器衡量续写。
