CORRECT 把已知失败轨迹压缩成可复用的错误 schema，借助检索增强 LLM 定位新轨迹中的责任 agent、错误步骤和原因。

标注旧失败 → schema 缓存 → 语义检索 → 对照新日志定位

拿一个输入走通方法

旧失败里，agent 把工具返回的“可用数量”误当成“总数量”；新任务也出现数量相关错误。

  1. 离线从带标注的旧日志提炼 schema：特征是混淆相近数量字段，条件是引用结构化工具结果，启发规则是核对字段含义与来源。
  2. 聚类、去重后将 schema 存入缓存，而不是保存所有原始长日志到提示中。
  3. 新失败轨迹经 embedding 检索出该模式，LLM 再看本次工具结果与 agent 陈述。
  4. 只有本次证据也支持混淆字段，才据此判断责任 agent、原步骤与原因；相似模式不是自动成立的结论。

关键设计为什么需要

schema 是调查提示和可复用错误知识，不是可直接套用的金标；当前轨迹仍是归因对象。

术语就地解释

signature：错误特征；context：适用情境；heuristics：识别时应检查的规则。

要解决什么？输入与输出

输入

带有错误步骤与原因标注的历史轨迹，用于建库；线上输入一条新的多智能体执行轨迹。

输出

责任 agent a*、错误步骤 s*、原因/置信信息 c；核心输出是错误识别，不会自动修改 agent 或恢复执行。

原文方法图 原文 Algorithm 1：CORRECT 离线建库与在线识别 · PDF p.4

方法怎样运行

1
离线提炼错误 schema

每个 schema 包含错误特征（signature）、发生条件与上下文（context）、用于识别的启发规则（heuristics）。

2
构建缓存

把相似失败轨迹聚类，筛选、压缩重复 schema，形成可复用错误知识库。

3
检索相似模式

将新轨迹嵌入，按余弦相似度取 top-k schema，而不是把大量原始历史日志直接塞进 prompt。

4
定位当前错误

LLM 结合目标轨迹和检索到的 schema，推断责任 agent a*、决定性步骤 s*、原因 c。

5
根据反馈维护缓存

新颖且经反馈确认的失败加入新 schema；高频 schema 可生成多个改写候选，用旧轨迹回放比较后更新。

sim(T, Sᵢ) = cos(embed(T), embed(Sᵢ)) → retrieve top-k → LLM returns (a*, s*, c)

实验读数

Who&When

GPT-5 在算法生成子集的 Acc@0 从 18.3% 提至 38.1%（+19.8 个百分点）；Acc@0 要求命中精确错误步骤。

CORRECT-Error

作者构建 2,000+ 条轨迹、7 类任务；在该基准上报告平均错误定位准确率提升，Acc@5 平均 +28.7 个百分点（GPT-4o-mini schema 设置）。

边界与阅读结论

关键边界：CORRECT 本身做错误定位，不是修复算法。论文另行测试从定位步骤定向重启，Who&When 手工子集上的端到端成功率从 10% 到 20%；这是“定位结果可用于下游恢复”的实验，不等于 CORRECT 自动完成修复。作者也指出错误标签可能有主观性，语义检索信号是否最佳仍待研究。

论文定位

多智能体失效归因/定位。适合作为 DoVer、MARS 的诊断前端或比较基线；不能单独算完整的“MAS repair”。

一句话记忆：记住：它把历史失败变成可检索的结构化规则；输出“哪一处像过去的错误”，不直接执行改错。

创新点｜具体改了什么

最吸引人的点 （整理者判断）

保留的不是“这道题以前错过”，而是“在什么条件下，什么行为像一种已知错误”。
