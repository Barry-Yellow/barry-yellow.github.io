问题变体训练表示 → 细/粗故障匹配 → 局部或编排反思 → 确认后积累

拿一个输入走通方法

出行问答中，某 agent 把距离直接当时长；另一种失败则只是单 agent 的汇率小数位算错。

  1. 离线将语义相近问题的推理构造成对样本，训练单 agent 的 Reasoning Encoder 和系统级 Trace Encoder。
  2. 每个 agent 完成一步，当前片段向量与细粒度历史故障库匹配；全体结束后再用全轨迹向量匹配粗粒度库。
  3. 命中具体计算 agent 的模式时，触发局部反思；若只有协作流程层面的历史故障吻合，则触发编排反思与重新规划。
  4. 未识别的新失败可走诊断及专家确认，再加入相应粒度的故障库，为以后检测复用。

关键设计为什么需要

粒度决定改哪里，避免任何异常都重做整条流程。表示训练不需故障标签，不代表故障知识库无需专家确认；原文未给完整匹配阈值，不能据此臆造。

术语就地解释

embedding：将推理片段编码为可比较向量；intra/inter/rank 损失分别约束片段、编排和前缀—完整轨迹关系。

任务与输入输出

  • 输入：当前系统推理片段／完整轨迹、历史故障知识；离线表示训练使用问题变体产生的推理。
  • 中间结果：agent 推理 embedding、系统轨迹 embedding、相似历史故障及细／粗粒度检测。
  • 输出：故障提示与诊断，触发 agent 局部反思或系统编排反思；经专家确认的新知识回流。

p.3 · §3 · Fig.1

中文标签与阅读顺序

  • 先读左图：Representation Model（表示）↔ Failure Knowledge（故障库）→ Step-Wise Detection（逐步检测）→ Reflexive Mitigation（反思缓解）。
  • 再看右图：距离直接当时长属于编排层问题；汇率计算位数错误属于单 agent 问题。

p.3 · §3 · Fig.1

方法：按执行顺序读

  1. 离线造对：对系统问题／agent 问题作变体，运行得到相似语义的轨迹与片段，构造正负样本。
  2. 学习表示：Reasoning Encoder 编单 agent；Trace Encoder 聚合这些推理 embedding，学习跨 agent 编排。
  3. agent 完成一步后检测：将当前推理向量与细粒度故障知识匹配；全体完成后，将全轨迹向量与粗粒度库匹配。
  4. 按粒度缓解：已定位具体 agent 则做 model-centric 反思；只知道全轨迹有错则做 orchestration-centric 反思与重规划。
  5. 确认与积累：用户判最终答案错误时，可调用诊断方法并经专家核实，补充两种粒度的历史故障知识。

p.3 · §3 · Fig.1

前作不足 → 本文设计

相关做法的不足本文如何处理
A2P／RAFFLES 等逐条轨迹的大模型推理耗时把已遇故障编码成可复用表示，运行时优先匹配历史。
通用文本 embedding 难保留推理与协作层次用 agent／系统双层编码和推理作用域对比学习。
只有全局异常标记难决定改哪个部分细／粗粒度知识分别触发单 agent／系统编排反思。

判断依据与关键细节

  • 表示训练不使用故障标签：基于“语义相似问题常产生相似推理结构”的假设，由问题变体构造学习样本。
  • 目标：L=λ₁L_intra＋λ₂L_inter＋λ₃L_rank；分别保持单 agent 语义、跨 agent 协作关系和前缀／完整轨迹一致性。
  • 故障知识仍需确认：无监督表示训练不等于知识库不需要故障解释与专家审核。
  • 实现空缺：正文未给出匹配阈值、完整负样本实现和细致训练／数据划分配置；不能从图推定可直接复现。

p.4 · §3.2 · Fig.2 · Eq.1

相对近邻的变化

  • 围绕相对固定系统中的重复故障，组织“表示学习—历史匹配—反思—知识更新”循环。
  • 单 agent 与跨 agent 两种作用域共同训练，并加入部分前缀到完整轨迹的排序一致性目标。
  • 将检测粒度与缓解粒度对应：局部 agent 与整体编排各有干预入口。

p.3 · §3 · Fig.1

最值得记住

  • 最吸引人的点（整理者判断）：历史知识命中哪个粒度，就在对应粒度反思，避免所有异常都重做整个协作流程。

解读 · p.4 · §3.1

结果与适用边界

  • 作者初步结果：三个系统上的故障诊断 F1 为 63.23%／78.76%／69.51%，并报告约 5 秒的平均检测延迟。
  • 边界：短文为初步评测，训练和评测配置披露有限；主要围绕固定系统重复模式，无法据此证明陌生系统或新故障上的通用可靠性。
