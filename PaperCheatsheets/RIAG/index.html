事件解析 → 文档版本/配置键 → 缓存命中或最多四次推理

拿一个输入走通方法

查询先绑定不可变文档版本 v1，再切到 v2，稍后因新绑定又回到 v1；推理配置不变。

  1. 每次先只依据已到达事件，按生效/撤回规则确定当前有效版本；不是最后收到的事件一定获胜。
  2. 第一次遇到 v1 无缓存，solver/checker 在互看之前各提交；一致且格式有效可结束，否则进入有限审计/修复。
  3. 切到 v2 因版本键不同而另算；后来回到同一个 v1，键不包含路由绑定事件，所以可以直接复用旧缓存。
  4. 若 v1 内容相同但版本 ID 或角色模型、策略、种子等配置变了，键仍变，必须重新计算。

关键设计为什么需要

先选对正在解哪份文档，再谈答案复用。初始互不暴露保证的是没看同伴答案，不保证两模型错误统计独立；修复后也没有再独立验证。

术语就地解释

世界时间：事件何时生效；到达时间：系统何时知道；κ：版本与推理配置的规范化哈希键。

原论文 Figure 2 · PDF 第 5 页

原图裁切：先读左侧事件与查询的时态选择，再看右侧精确缓存键；下方工作流决定命中直接返回，未命中进入中间的 solver/checker/auditor/repairer。p.5 · Fig.2

输入 → 输出

  • 输入：按到达顺序可见的事件前缀 Hₜ、查询的世界时间 wₜ，以及固定内容的不可变文档版本与推理配置。
  • 输出：(被选中文档 ID,答案)，并记录支持该版本的绑定事件、缓存记录和调用暴露关系。
  • 必须区分“何时收到”与“何时生效”：迟到事件不自动覆盖更晚生效的绑定，撤回可重写后续查询对历史的判断。

p.4 · §3 / 示例

原图标签

  • Temporal document selection＝有效文档解析；Version-keyed memoization＝按版本缓存；Exposure ancestry＝看过哪些此前输出。
  • 蓝色虚线 challenge＝触发争议审计；红色虚线 repair-request＝审计要求修复；黑箭头＝输出进入后续提示。

p.5 · Fig.2

方法流程｜5 步

  1. 解析：仅使用当前已到达事件，过滤尚未生效、已关闭或已撤回的绑定；按生效时间、到达时间和 ID 确定选中文档。
  2. 查键：将文档内容/版本、数据集、策略、角色模型、种子与解码配置规范编码并哈希；同键才复用。
  3. 双提案：solver 与 checker 在互看输出前各自提交；两者格式有效且答案相同则两次调用结束。
  4. 条件审计：不同或格式失败时 auditor 看两份记录；有理由、格式有效且无需修复则三次结束。
  5. 有限修复：否则 repairer 看前三份记录，最多第四次；有效修复也标 unresolved；失败依次回退初始有效答案或空值。

差异｜路由变化不一定让旧解失效

绑定事件决定现在解哪份文档；文档版本决定旧解能否复用。回到同一版本可以命中缓存，换版本或推理配置就强制重新算。p.6 · §4.3–4.5（续 p.7）

前作不足 → 本文设计

前作或常见做法的不足本文对应设计
Debate、Refine、GoA 等通常已给定一个固定任务。加入到达时间/生效时间/撤回语义，显式评分文档选择和答案的联合正确。
每次事件后重算浪费；无条件复用会返回旧任务答案。先解析有效版本，再用文档版本 + 推理配置做精确缓存。
交换过答案后的相同结论可能来自传播。初始两个提案互不暴露；记录每次调用祖先，审计和修复视作裁决。

p.3 · §2（续 p.4）

最值得记住的键

  • 键包含内容和版本 ID，刻意不包含路由绑定事件：任务被切走后再次回来，原解仍可复用。
  • 缓存限于 episode；失败和预算耗尽也记入，避免反复请求重新获得四次预算。

p.6 · §4.3–4.5（续 p.7）

具体变化｜作者方案

  • 求解前端：把时态解析变成零模型调用的确定性过程，再交给黑箱 reasoner。
  • 图的含义：节点是具体模型调用，边是可审计的输出暴露，不把 agent 通信拓扑本身当核心目标。
  • 预算结构：新键通常两次，分歧时最多四次；超时/畸形回复也消耗槽位，无隐藏重试。

p.6 · §4.3–4.5（续 p.7）

最吸引人的点

  • 整理者判断：把“绑定变了”与“文档内容变了”拆开，才能既恢复旧路线又复用其旧解，缓存策略因而可直接写成严格规则。

解读 · p.6 · 整理者判断

作者实验与解释

  • 六种动态任务集上，同质 RIAG 联合正确率 54.24%、0.62 次调用/查询；Debate 为 32.22%、18.00。
  • GoA 加时态前端后也提升，但控制包还改变角色卡/温度，论文明确不把收益解释成解析器的单独因果效应。

重要参考 · 已核验题名与官方链接

  • Graph-of-Agents: A Graph-based Framework for Multi-Agent LLM Collaboration：按模型卡选 agent、构图并双向传消息后聚合；RIAG 的图则记录实际调用及输出暴露关系。
  • Improving Factuality and Reasoning in Language Models through Multiagent Debate：多个实例交换论证改进固定任务答案；RIAG 先确定当前有效任务，并保留初始互不暴露提案。
  • Self-Refine: Iterative Refinement with Self-Feedback：迭代自反馈改写；RIAG 用分歧/格式检查触发有限 audit/repair，而非每次完整展开。
  • Mixture-of-Agents Enhances Large Language Model Capabilities：分层读取其他 agent 输出并聚合；RIAG 不把已读同伴内容后的赞同算作独立佐证。

p.10 · References（续 pp.11–12）

边界与阅读范围

  • “独立”指互不读取同伴答案，不保证错误统计独立；格式检查也不验证数学或程序语义。
  • 不可变文档与固定事件规则是评测控制；新内容须创建新版本。缓存不做命题级依赖推断，修复答案没有后续独立复核。
