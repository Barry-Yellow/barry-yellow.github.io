拿一个输入走通方法

同一任务多次运行：一些失败运行把旧价格当现价，成功运行通过新查询取得价格。

  1. 将每次日志抽成三元组，例如〈检索者，读取价格，旧价格被采纳〉；语义聚类把不同措辞合为可统计行为。
  2. 对各次运行记录该三元组是否出现、出现几次，以及任务最终成功还是失败。
  3. 用谱公式衡量它与失败的关联，再结合 agent 覆盖、动作比例和当前失败中的重复频次修正。
  4. 仅对原失败轨迹中的三元组排序，返回 top-1；不是直接从任何失败运行里摘一个动作作为修复。

关键设计为什么需要

LLM 负责把自然语言变成可比单位，统计负责跨运行关联。若日志抽取/聚类错了，频谱也会建立在错误单位上；关联排名不等于干预证明。

术语就地解释

三元组的 State 指动作后的状态；谱是跨成功/失败执行的覆盖统计，不是 SOAP 的表示矩阵 SVD。

原图 Fig.3｜重放抽象后做谱分析

流程：① 原始失败日志与同任务多次重放；② LLM 分块抽取 Agent–Action–State，分层聚类合并语义相近表达；③ 形成覆盖矩阵和频次矩阵；④ 组合 Agent 行为、Action 行为特征计算 suspiciousness；⑤ 在原失败轨迹中排序并输出 top-1。原图 Fig.3 · PDF p.7 · §4

任务设定｜它要识别什么

  • 给定一条失败执行轨迹，以及同一任务的多次独立重放轨迹（重放可能成功或失败）。
  • 把每条日志中的行为表示为三元组 ⟨Agent, Action, State⟩，最终从原失败轨迹中识别错误决定动作及其 Agent。
  • 核心假设：导致失败的动作/状态模式会在重放中呈现可利用的频率或分布差异。
  • 与直接让 LLM 阅读完整日志相比，先做规范化和聚类，再做统计排序。

来源：§2、§4.1，PDF pp.3–8。论文把根因表述为导致决定性错误状态的动作。

阶段一｜日志转为可比较轨迹

  1. 对原失败任务做 k=20 次独立重放，收集原始执行日志。
  2. 把长日志切成较小片段，LLM 逐段抽取 Agent、Action、Action 后的 State。
  3. 对候选三元组做 Agent 聚类、Action–State 聚类，合并语义相近但表述不同的实体。
  4. 统计每条轨迹中的三元组出现/覆盖，并记录任务最终成功或失败，供谱公式使用。

默认抽象模型为 Qwen2.5-72B；λ 默认 0.9。轨迹重放需能重新运行相应 MAS。

来源：§4.1、§5.1，PDF pp.7–11。

运行成本｜复现要考虑的现实门槛

  • 平均每条失败归因约 105 分钟；范围 38–248 分钟。
  • 126 条算法生成日志：重放 21 分钟、抽象 6 分钟、聚类 11 分钟。
  • 58 条手工 MAS 日志：重放 136 分钟、抽象 103 分钟、聚类 9 分钟。
  • 谱分析本身在获得抽象轨迹后通常少于 1 分钟；主要开销来自重跑 MAS 与 LLM 日志处理。

来源：§5.2，PDF p.12；k=20。成本依赖重放系统的可用性、复杂度和论文实验环境。

有说服力的设计点

  • 把“语义归一化”和“跨运行统计”拆开，减少原始日志自然语言差异的干扰。
  • 不只统计动作出现在失败运行的次数，也通过 Agent 覆盖/频率修正活跃度与行为基线。
  • 包含同一谱框架替换公式、参数敏感性和不同复杂度分析。

证据边界

  • 实验集中于 Who&When 的 184 条轨迹；外部基准、跨任务泛化未在本研究中建立。
  • 方法依赖同任务可重复执行，且实现/访问 MAS；无法重放时不适用。
  • 长日志抽取和聚类依赖 LLM，存在表述抽取与聚类误差；输出 top-1 也不表达不确定性。
  • 高耗时是实测设计成本的一部分，不能只把后续谱计算视为总成本。

基于 §5.1–5.2、§6 Threats to Validity 的归纳。

与前两篇的关系

FAMAS 与 SOAP 都用“失败轨迹”做步骤/动作归因，但 FAMAS 需要同任务多次重放，利用成功与失败运行的谱差异；SOAP 使用无步骤标签失败轨迹的表示谱，并借注意力把下游信号回传。LongRCA Bench/RCTA 面向更长自然失败日志，分别评估角色与最早根因步骤，靠分段候选召回及交接证据追溯。

任务定位摘要，非统一基准上的直接比较；三篇实验数据、粒度及模型协议不同。

最短复述

FAMAS 将经典频谱故障定位迁移到多智能体：同一任务重放 20 次，把各次日志规范成 Agent–Action–State，综合跨轨迹失败关联、Agent 行为基线和当前失败轨迹内的重复异常，为原失败轨迹动作排序。Who&When 上 top-1 Agent / Action 准确率为 57.61% / 29.35%；主要限制是对可重放系统的依赖、单一基准评估和较高运行时间。

核心思路

同一任务重复执行，先把自然语言日志统一成 Agent–Action–State，再用跨运行的成功/失败关联给原失败轨迹中的动作排序。

已有做法与具体不足本文的对应设计
直接 LLM 通读归因不易利用重复运行之间的差异将传统频谱定位迁移到 MAS 跨运行统计。
自然语言动作表达不同，不能直接当同一程序语句统计先抽象并聚类 Agent–Action–State。
不同 agent 活跃度与动作重复会干扰简单频次加入覆盖、频率比例与局部频次修正。

创新点｜具体改了什么

  • 语义归一化负责可比性，谱分析负责统计归因。
  • 面向 MAS 行为特点调整经典可疑度。
