启动时先给智能体排固定串行顺序；读取只看该顺序允许的状态，乱序写用逆操作重排，较早智能体的新写仅通知较晚读者，由读者判断并局部修复受影响计划。

固定 rank → 过滤读 → 较早写通知 → 语义修复/可逆写排序

拿一个输入走通方法

固定顺序 A 在 B 之前；B 提前读到库存 10 并计划取 9，随后 A 把合法库存改为 8。

  1. 中间件记录对象的读写足迹；B 读到的是其 rank 允许的物化前缀，不应直接看到排序在 B 后面的写。
  2. A 的较早 rank 写改变了 B 已读的对象，运行时只向 B 发送合法值更新通知。
  3. B 在下一次推理前判断计划是否仍成立；取 9 已不符合库存 8，应重读并修改依赖该旧值的动作。
  4. 若 B 的可逆投机写已先发生，运行时还要撤下乱序后缀、按 rank 插入和重放写；不可逆写则按规则等待。

关键设计为什么需要

通知修读者计划里的旧前提，逆操作修外部写的次序，二者不是同一件事。最终串行等价还依赖 agent 正确自修复等假设。

术语就地解释

rank：预先固定的串行位置；GlobalQuiet：所有 agent 静止、通知已清空的最终检查点。

问题与输入输出

  • 问题：共享仓库/集群里，写集合不重叠也可能因读到旧前提而产生非串行结果；锁会等长推理，OCC重试丢掉已算工作。
  • 输入：并发任务、固定rank顺序、对象状态及每个工具声明的读写足迹；可补偿写还要有逆操作。
  • 输出：全部智能体静止且通知清空时，与预定串行顺序一致的最终状态；该保证依赖A1–A3。

p.1 · 摘要 / §1

图旁中文对照 / 阅读顺序

  • 左 Filtered read：只返回rank≤自己的轨迹前缀物化值；屏蔽“排在自己后面”的写。
  • 中 Notification：低rank写者更新了高rank读者读过的对象，向后者通知新合法值；由LLM判断计划是否受影响。
  • 右 Undo / apply：若写入到达顺序违背rank，逆向撤下较晚写，按rank插回/重放；无逆操作的写等待前序提交。

p.7 · Figure 3

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 登记对象与工具：每次共享访问必须经过中间件，并声明真实读写集合；ToolSmith可把新操作封装成带绑定和逆操作的工具。p.6 · §5.1；p.7
  2. 过滤读取：每对象保留按rank排序的写轨迹；读自己的合法前缀，读改写型操作必须组合此前写；可用快照、缓存读结果或临时undo服务。p.8 · §5.3
  3. 投机写入：可逆写即时作用于共享状态；晚到的低rank写必要时先撤掉高rank后缀，再依序恢复，维护最终物化次序。p.8 · §5.3
  4. 单向通知并修复：只有低rank→高rank；读者下次推理前收到变化，可忽略无关冲突，或重读并改写/撤销依赖该旧值的动作；静止读者也可被重新唤起。p.8 · §5.3
  5. 等待收敛：无逆操作的写先等所有低rank提交；所有智能体无待写、已消费通知且无通知在途时，达到GlobalQuiet并检查串行目标。p.8 · §5.3

差异、证据边界与必读前作

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.12 · §8；p.13–14 References

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
2PL / OCC：长推理放大持锁等待、死锁以及整任务abort-and-retry的成本。把冲突处理交给语义通知与局部修复，保留不依赖旧值的推理成果。
写分区 / fork-merge：前者未隔离跨对象读取；真实集群也通常不可fork。读视图按固定rank过滤，并用对象写轨迹和补偿让实时状态最终匹配预定顺序。
无条件双向广播：每次自修复又刺激另一方，可能反复改写而活锁。通知严格从低rank流向高rank，形成有向无环依赖；并对乱序写施加补偿排序。

p.12 · §8；p.13–14 References

创新差异｜作者主张，按机制归纳

  • 语义分工：运行时知道可能冲突，LLM决定是否破坏任务前提并局部修复。
  • 两条修复通道：上下文旧读由通知解决；物理乱序写由运行时逆操作解决。
  • 正确性范围：定义notified serializability，并在固定顺序、足迹正确、代理正确自修复等假设下证明静止时等价。

p.7 · §5.1–5.3；p.8

结果与使用边界

  • 作者报告：10个构造竞争场景、100次试验中MTPO的Invariant-OK为93%，串行98%；剩余差距来自收到通知后判断错误。
  • 关键假设：单独执行能成功；所有访问走声明足迹的工具；代理能正确识别语义冲突并修复，均不是由协议自动保证。
  • 应用边界：任意bash不能直接加入；无逆操作的写需等待。目标是GlobalQuiet时串行一致，非执行全过程都已达到最终一致状态。

p.11 · Figure 5；p.10 §7.1–7.2

最吸引人的点｜整理者判断

  • 把并发错误分成“读者脑中的旧前提”和“外部状态的写顺序”：各给一个修复通道，避免只处理文件冲突。

重要参考｜题名、官方链接与摘要已核对

  • Atomix: Timely, Transactional Tool Use for Reliable Agentic Workflows：摘要核对：以进度前沿控制工具效果最终结算；CoAgent把修复提升到代理读视图与语义计划层。
