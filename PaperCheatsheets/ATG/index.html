粗任务 → 保接口细化 → 原子工具执行 → 定位祖先/局部修复

拿一个输入走通方法

要生成一份“查商品→比较→给推荐”的计划；查商品这个粗节点的输入是条件 q，输出应是商品列表 L。

  1. 规划器把“查商品”展开为工具子图，例如查目录、取详情、整理列表；子图整体仍要接收 q 并输出兼容的 L。
  2. 递归展开到每个节点都是一次可调用工具，保留各轮粗细图的对应关系。
  3. 执行器只在前驱输出齐备时调度；独立分支可并行。执行前模拟检查只是 LLM 检查，不是真实调用成功。
  4. 若详情工具接口出错，沿编译历史定位适当祖先，替换该局部子图；对外仍输出 L，再接回原有“比较”节点。

关键设计为什么需要

接口约定让局部修改能够重新接入周围图；图不变并不保证旧结果语义仍有效，受影响下游还需按依赖处理。

术语就地解释

DAG：无有向环的依赖图；接口：周围节点期望接收/产生的数据含义与格式。

问题与输入输出

  • 问题：长文本轨迹把子任务依赖埋在上下文里，复用正确结果和定位局部错误都困难。
  • 输入：用户目标、约束、期望输出，以及有明确输入输出接口的工具集合。
  • 输出：所有节点均可直接执行的原子任务图，以及按该图执行得到的任务结果。

图旁中文对照 / 阅读顺序

  • Planning：粗任务→细子图→单次工具调用；每层都保留父任务的外部输入输出。
  • Execution：Thought Experiment 是执行前的LLM模拟检查；通过后按依赖调度独立分支。
  • 红色回路：失败定位→局部子图修复→接回原图；其余已验证区域冻结。

p.3 · Figure 2

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 递归编译：把非原子节点替换为子图，子图消耗原输入并产生兼容的输出；仅提供当前节点直接相关上下文。p.5 · §4.1
  2. 保存演化：记录每轮粗到细的图，直到每个节点 (输入,工具,输出) 可直接调用；边表示输出被下一节点作为输入。p.5 · §4.1
  3. 先做模拟检查：检查工具适配、缺失步骤、依赖假设、接口与约束，记录暴露问题的节点及错误类型。p.5 · §4.2
  4. 真实执行：前驱完成且所需输入就绪时才运行节点；无依赖冲突的分支可并行，记录输入/输出/状态/错误。p.5 · §4.2
  5. 失败修复：沿演化历史找失败节点的最低公共历史祖先，覆盖必要上游与受影响下游；替换工具/补节点/调边，保持外部接口后接回。p.6 · §4.3

差异、证据边界与必读前作

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.3 · §2；p.10–12 References

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
ReAct / Reflexion式轨迹：控制状态主要在文本历史中。把输入输出依赖、执行状态、就绪条件直接放进可执行图，减少重复从全文推断下一步。
PoG等显式规划：任务图能支持并行，但本文强调还需统一执行与恢复。记录保接口的递归编译历史，给后续失败定位和可复用边界提供结构。
全局重规划：一个错误也可能丢掉已完成的有效计算。定位历史祖先，只修改失败及受影响子图，冻结其余有效区域。

p.3 · §2；p.10–12 References

创新差异｜作者主张，按机制归纳

  • 编译历史：保留从语义任务到原子工具的对应关系，修复时能回溯到错误规划范围。
  • 保接口替换：父节点与子图兼容，局部重新分解时仍能接回周围图。
  • 统一控制：同一图承担模拟检查、依赖就绪判断、并行调度和局部修复。

p.4 · §4.1–4.3；p.5–6

结果与使用边界

  • 作者报告：Llama-3-8B下，ALFWorld/WebShop/ScienceWorld平均奖励为63.65/68.36/56.79（Table 1的百分制）。
  • 重要区别：所谓“最小必要子图”由失败节点、历史祖先及依赖确定，正文未给全局最小代价优化证明。
  • 限制：依赖LLM分解能力；噪声与长程依赖使定位困难；只验证文本环境，简单任务可能被额外控制开销拖慢。
