观察准入 → 有效依赖传播 → 修复提案 → 带全部观察再准入

拿一个输入走通方法

调度任务中某设备延迟，agent 提议把依赖作业顺延；修复候选还没提交时又收到第二次故障。

  1. 第一次故障先作为观察提案经过准入，得到已提交的扰动后 StateView，而不是直接把 LLM 解释当世界状态。
  2. 沿有效依赖传播影响，形成有限范围的重定时/资源分配候选；候选无提交权，仍要满足约束 C、迭代 K 与扰动预算等检查。
  3. 第二次故障到达时，保留恢复点及未处理观察集合，把新观察加入；旧在途修复不能静默吞掉它。
  4. 基于恢复点和累计观察重建候选并再准入；通过才更新已提交状态，失败则拒绝或升级。

关键设计为什么需要

修复器也可能错，因此故障观察和修复提案必须分开保存；否则删掉故障记录也能制造“修复成功”的假象。

术语就地解释

StateView：当前已提交状态投影；C：可检查约束；准入 gate：决定候选是否允许成为已提交事实的运行时边界。

输入 → 输出

输入：候选转移 p（对象/操作、依赖、世界假设、冲突 scope、证据），可执行约束 C，当前 StateView；故障报告先作为候选观察进入。

输出：已准入转移及其状态投影；或带原因的拒绝/升级。外部副作用在提交后经 outbox 发出。

Table 1 · p4§4 · p13

状态不是一份聊天记录

CTL：只追加的已提交转移日志。补偿/替代追加新记录，旧事实保留。

StateView：从 CTL 投影的当前有效状态，排除已补偿、替代或失效记录，并保持依赖链完整。

ACR：持久义务，含触发条件、guard、continuation、补偿与到期条件。

§2.1 · p4§4 · p13

运行一次：5 个具体动作

  1. 封装提案：解析租户、操作/幂等键与冲突 scope。
  2. 读取见证：取当前 StateView 和仍有效、可查询的证据。
  3. 执行 C：查状态机、陈旧假设、依赖闭合、补偿安全；修复须证明故障已解决，或保留有效、可查询的触发证据。
  4. 处理并发：重叠冲突 scope 串行化或拒绝；ACR 就绪与补救也只能提案。
  5. 原子提交并投影：通过才追加 CTL、更新 StateView；否则留下拒绝原因。

02 / 局部修复、前作关系与边界读懂 repair 的中间状态§3.2 → §5.7 → S13

原图裁切，PDF p12；示意图。先看上行：故障 → 有效依赖闭包 {t₃,t₄,t₅}（橙）→ 闭包外保留（绿）；再看下行全局重排。δmax 为位移/扰动预算，K 为迭代上限；图以编辑半径作直观示意。Fig.2 · p12

修复的 3 个中间产物

  1. 新状态：故障观察经准入，得到扰动后的 StateView；ACR 的 ready/breached 也须先提交。
  2. 受影响集合：沿当前有效依赖传播延迟、资源释放与 guard 失效，只改必须变化的后继。
  3. 修复提案包：在 δmax、K 内重定时/重分配；运行时判定可逆性，越过不可逆边界则否决；再准入才提交。

超预算/轮数则升级并回到最近恢复点，用依赖闭合补偿逻辑撤销后续效果。

§3.2 · p10修复阶段/命题5–6 · p11

修复途中又坏了，观察不能丢

保留最近已提交恢复点 Sₖ 与尚未被修复吸收的观察集 Dₖ；新故障先加入 Dₖ，旧在途修复仍只是提案。基于 R(Sₖ, C, Dₖ) 重新构造并准入，陈旧候选拒绝。

“无记忆”仅指不依赖失败/中止的提案历史，仍须记住全部未处理的世界观察。

  • 主动数据库 ECA / provenance：触发动作与事后审计 → ACR 唤醒仍须准入；故障证据直接成为修复准入条件。

作者贡献与最值得记住的点

  1. ATP 权限边界：从“请求怎么提交”前移到“生成请求有没有资格提交”。
  2. 四项安全性质：权限隔离、串行等价准入、证据保留修复、义务约束；外加有界修复。
  3. Mnemosyne 运行时：日志、投影、ACR 与补偿在同一准入边界下实现。

记忆点（整理者判断）：修复器也不可信；未证明故障已解决时，不能删触发证据制造成功。

实验能说明什么

6 个调度实例均恢复可行：LCRP 平均改 7.2 个操作，全局重算 59.8；后者原始 makespan 更好。该结果来自配套调度 harness，不是通用语义修复实验。

12 个受控中断场景全部拒绝陈旧修复，丢失观察/无效/重复提交均为 0。两次小规模 live-LLM pilot 共 80 提案，0 无效提交。

边界：C 未覆盖的危险、未声明的隐冲突不受保证；须 gate closure。无全局最优、普遍语义正确或生产规模结论。
