分段召回 → 原步骤/交接对照 → 根因与角色分别输出

拿一个输入走通方法

planner 先交代“只订两晚”，但用户实际要求三晚；executor 完全照着订了两晚，轨迹最终失败。

  1. 日志分段，RCTA 在各段摘要中召回“不足三晚”的候选执行步骤，保留原步骤 ID。
  2. 检索发给该 executor 的最近前序交接，回读指令和执行的原始文本。
  3. 若错误已在指令中且后来未修复，根因应向指令步追；若指令正确而执行者少订一晚，则保留执行步骤。
  4. 分别输出责任角色与最早决定性根因 ID；不能从所选根因步的发言者机械推出角色标签。

关键设计为什么需要

摘要负责找候选，原消息负责判；执行者“做了错事”和“先引入错误”并非同一判断。

术语就地解释

未修复的决定性错误：最终失败前仍起作用的关键偏差；后来已修好的旧错误不作本次根因。

标注目标｜两种能力独立评分

  • 责任角色：对最终评估失败负责的轨迹内角色。
  • 根因步骤：最早引入、且未在最终失败前修复的决定性错误步骤。
  • 根因步骤可能是 planner 的错误交接；后续 executor 只是照做，不自动承担责任。
  • 角色不从根因步骤的发出者推断；角色准确率与根因定位准确率分开算。
  • 任务是完整失败日志结束后的离线诊断，不测在线预警。

来源：§1、§3.1，PDF pp.2、4。修复过的旧错误和仅传播/暴露错误的后续步骤不作根因。

RCTA 三步｜摘要负责找，原文负责判

  1. 分段：按规则切成连续区段，保留原始步骤 ID；边界附近最多带 5 步重叠上下文，不调用 LLM。
  2. 候选召回：每段一次 LLM 调用产出摘要及候选步骤；再汇总相邻段摘要形成全局进度大纲。
  3. 回溯归因：取候选步骤的原始文本，检索相关的前序交接指令。若错误已在指令中，根因选指令步；若执行者偏离指令或引入新错，选执行步。单独输出角色与根因 ID。

含 m 个片段时，主流程约需 m+2 次初始 LLM 调用；无效输出可按程序化检查反馈重试一次。

来源：§5.1–5.3、Appendix E，PDF pp.8–9、17。结构校验可证明 ID/引用有效，不等于诊断语义正确。

结论边界

  • 根因精确准确率最高 24.1%，明显低于角色准确率 51.1%；角色判断不能替代根因定位。
  • 基准只评价角色与单个最早根因索引；RCTA 输出的中间因果链未被评分。
  • 仅测失败结束后的离线诊断；不支持在线干预或提前预警结论。
  • TravelPlanner 占 60.1%，数据域有明显不均衡；跨域泛化需另验。
  • 这是一个基准加方法的工作；标注根因仍需专家式判断，精确根因标签本身有较低的人际一致率。

来源：§4、§6–7，PDF pp.7–12；数据比例见 Table 2 / Fig.3。

最短复述

LongRCA Bench 将长轨迹失败诊断拆成两个独立目标：找对责任角色，以及找对最早未修复的决定性错误步骤。RCTA 通过分段摘要降低搜索范围，再把候选错误与更早的交接指令逐条对照。它在同一评估设置下优于所测基线，但精确根因定位仍困难，论文也没有评估完整因果链或在线诊断。

阅读范围：摘要、§1、§3–7，重点 Fig.1–2、Fig.5、Table 2–4；arXiv:2608.15242v3 · Semantic Scholar。

核心思路

将长轨迹诊断拆成“哪个角色负责”和“最早未修复的决定性错误在哪一步”；RCTA 先分段找候选，再回看原始交接指令归因。
