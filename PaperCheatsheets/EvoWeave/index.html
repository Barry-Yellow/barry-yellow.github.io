机制｜带条件检索、连接、执行

图可达只产生候选片段；输入是否齐全、实体是否一致及写入是否安全，要在当前环境继续检查。p.4 · Fig.2 / §3.2–3.3

五步运转

  1. 先规划：由任务与当前历史生成剩余步骤 DAG，不先按已有记忆反向拼任务。
  2. 检索操作：先过相似度阈值，再取每步 top-3；允许没有候选。
  3. 连接片段：只针对直接依赖，在候选边的终点到下一候选起点之间做有界 BFS。
  4. 处理缺口：连接失败记为缺口或预算截断；候选不一致则保留独立片段并暴露冲突。
  5. 执行与更新：主 agent 检查实际输入并行动；反思后对经验做结构、能力和契约校验，再发布。

p.3 · §3.1 p.4 · Fig.2 / §3.2–3.3 p.5 · §3.4

创新点｜相对前作的具体变化

  • 表示：操作是状态间转换边，并附输入输出契约、能力引用、来源和版本。
  • 组合：计划直接依赖驱动检索和连接，不只返回语义相近片段。
  • 记忆：具体执行证据与泛化经验分开，合并也需契约校验。

p.3 · §3.1 p.4 · Fig.2 / §3.2–3.3 p.5 · §3.4

最吸引人的点｜整理者判断

  • 把“检索相关”与“当前可执行”分开：找到一条路径，不自动意味着它能在当前状态使用。

一个贯穿例子

  • 任务：给合作者发邮件。检索“找联系人、起草、发送”三段操作，再检查草稿是否有正确收件人、发送接口是否可用；历史查论文步骤无需带入。

p.4 · Fig.2 / §3.2–3.3

证据与边界

  • AppWorld 消融中，给独立操作卡增加有向连接后，作者报告 Overall TGC 增加 2.08 个百分点；不能推出所有任务均受益。
  • 这是跨任务经验组合；单次失败轨迹修复后的旧节点有效性，需要额外状态与输入校验。
