从一条失败轨迹和可恢复的系统状态出发，MARS 搜索多种回滚与修复路径，再选出评分最高的修复轨迹。

状态节点 → 选择 → 回滚/引导/继续 → 部分评分 → 回传

拿一个输入走通方法

网页搜索走进了错误网站；有两个可能：较早检索词错了，或检索词没错而 agent 只是尚未找到入口。

  1. 树中一个节点保存当前轨迹与可恢复状态；UCT 决定先探索哪个有希望或较少尝试的节点。
  2. 分支一 Rollback 到检索前，再 Guided Repair 提示修正关键词，最多执行 L 步。
  3. 分支二保持提示不变做 Continuation，也只执行最多 L 步；即使尚无最终答案，也按失败类型与进展 rubric 评分。
  4. 分数回传影响后续预算分配；可以再回滚、再修正。终局成功仍需答案与工具证据核验。

关键设计为什么需要

部分 rollout 避免每个候选都跑到终点；保留多分支避免一次诊断把所有预算锁在同一条错误路径。中间高分不等于任务已成功。

术语就地解释

MCTS：在树上分配探索预算；UCT：平衡利用高分与探索少见节点的选择规则；L：一次续跑的步数上限。

要解决什么？输入与输出

输入

失败的多智能体执行轨迹 τ，以及每一步的序列化运行状态（对话、激活 agent、编排变量、记忆和工具结果）。

输出

预算内评分最高的修复轨迹；若得到通过验证的完整成功轨迹，可提前结束。

方法怎样运行

1
建立搜索树

根节点是原失败轨迹。每个节点保存系统状态、当前轨迹、上次诊断反馈 f 和分数 r。

2
选择候选节点

用 UCT 在高分路径与少探索路径之间取舍；节点深度与分支数受搜索预算限制。

3
诊断并检查诊断

LLM judge 对部分轨迹检查 14 类失败模式并评估任务进展；动作选择器先复核反馈，避免直接照单全收。

4
扩展三类动作

选择回滚到故障步骤、注入根因对应的引导修复，或不改提示继续执行。修复和继续都只 rollout 最多 L 步。

5
打分并回传

以 0–1 分级 rubric 衡量部分进度；将分数沿搜索树回传，保留当前最高分轨迹。完整答案需有工具证据支持并通过独立答案核验。

实验读数

StateMAS

1,310 条可回放失败轨迹；4 种编排结构 × 4 个 LLM backbone，覆盖 GAIA、AssistantBench。

报告结果

论文摘要报告：各设置相对最强基线的绝对提升为 3.0–12.1 个百分点；部分 rollout 用于控制 token 成本。

边界与阅读结论

作者列出的限制：StateMAS 基于 Microsoft Agentic Framework，其他框架需要适配状态快照和回放；任务以通用助理与网页导航为主；API 成本限制了部分设置的评测规模。此文为 v1 预印本，页面标注会议审稿中。

论文定位

真正的多智能体失败后修复。相较 DoVer 的单路径干预，MARS 将修复选择放进 MCTS 分支搜索。

一句话记忆：记住：MARS 搜的不是“谁错了”本身，而是“回到哪一步、施加什么修正、后续怎么走”这一串干预。

核心思路

把一次失败后的修复变成搜索：在不同回滚点、纠正提示和继续执行路径之间，用 MCTS 分配尝试预算。

以前文章的问题 → 本文如何解决

已有做法与具体不足本文的对应设计
DoVer 的顺序尝试可能过早押注一条修复路径，且主要编辑 orchestrator以树搜索保留不同修复分支，使用通用状态/动作接口。
标准 MCTS 全量 rollout 的成本高短程 partial rollout 加分类辅助的中间进度评价。
静态失败日志不能验证恢复构建带状态快照和回放接口的 StateMAS。

依据本文引言、相关工作及方法压缩整理；对照仅针对列出的做法。

创新点｜具体改了什么

  • 回滚、引导修复和无提示继续被拆成可组合搜索动作。
  • 在尚无最终答案时给部分轨迹评分，支持预算内分支探索。
最吸引人的点 （整理者判断）

诊断第一次猜错也不用整场作废：搜索树可以换回滚点、换建议，再从另一个分支继续。
