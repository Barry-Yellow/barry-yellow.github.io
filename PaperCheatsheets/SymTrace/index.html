先把干预前的模型与工具返回值固定，再只让锚点及其后续真实重跑；这样能检查成功是否来自预期改动。

边界快照 → 请求匹配/历史注入 → 锚点干预 → 实时新后缀

拿一个输入走通方法

原执行先检索，再由 LLM 读结果作决定；准备只在这个决定处注入纠正提示。

  1. Snapshot 记录模型/工具的请求—返回、依赖图和真实顺序；先前工具仍真实运行过。
  2. Replay 用相同任务和初态启动，在锚点前返回记录值；每个请求要匹配位置和规范化内容，不匹配就中止。
  3. 到选定 LLM 锚点才注入纠正提示，停止用历史返回代替真实调用，重新生成后续模型与工具交互。
  4. 比较恢复结果时，干预前可观测历史受控；干预后可以走不同路径，也可能因随机性再次失败。

关键设计为什么需要

固定过去使修复比较更有解释力；不等于只复制几条聊天记录，更不等于恢复了未记录且不可重置的外部世界。

术语就地解释

锚点：允许干预并恢复实时执行的模型调用边界；G 是依赖，O 是观察到的执行次序，二者分别记录。

输入 → 输出

  • 输入：原生 MAS 的任务 T、初态 s₀、配置 c、已发生的模型/工具交互，以及指定干预锚点。
  • 输出：重建且已校验的逻辑前缀 + 从锚点开始新生成的后缀轨迹。

原图标签与阅读顺序

  • Boundary Logging＝边界日志；Trace Construction＝事件依赖图与实际顺序；Replay Bundle＝可重放包。
  • Result Injection＝注入历史结果；Boundary Matching＝严格匹配请求；Live Resume＝恢复实时执行。
  • L＝LLM 调用，T＝工具调用，M＝消息/上下文；依赖图 G 与观测顺序 O 分开保存。

p.3 · Fig.2

方法流程｜5 步

  1. 记录：钩住 LLM 请求—响应和工具调用—观察，端点仍真实执行，保存边界值 R。
  2. 组织：构建数据/控制依赖图 G，另存实际事件顺序 O，连同 T、s₀、c 打包。
  3. 重启：按原任务与配置启动 MAS；到锚点前，用历史结果代替实时端点。
  4. 检查：逐个匹配事件位置与规范化请求，哈希校验复用节点；不匹配即中止重放。
  5. 干预：到锚点注入修复提示，恢复实时模型与工具，由原调度器生成后缀。

修复信号｜症状、差异与适用边界

SymTrace 是执行控制机制；Suspicious-Node Intervention 在其上选择可操作节点，并提供症状与证据。p.15 · App.F.1–F.2 / Alg.3

原论文 Figure 3 · PDF 第 16 页

原图裁切：从新完成节点出发：规则候选 → 语义确认 → 置信门限 → 暂停并回到可重放锚点；无症状则继续。p.16 · Fig.3 / App.F

四类症状与锚点

  • C1 任务约束违规；C2 重复或停滞；C3 未解决的运行条件；C4 计划—动作—结果不一致。
  • 规则无命中则不调用语义裁判；裁判可否决候选，不能新增规则外类别。
  • 按顺序找到首个满足融合分数门限的可重放 LLM 节点；分数结合局部证据、可修复性与位置，属于序数量而非概率。

p.15 · App.F.1–F.2 / Alg.3

前作不足 → 本文设计

前作或常见做法的不足本文对应设计
完整重试会同时改变失败前历史，难把收益归于修复。记录并严格重建锚点前缀，从干预处恢复实时执行。
MAST 等日志分析主要用于事后描述和定位。把事件依赖、顺序和实际返回值一起变成 replay bundle。
随机/末尾选点缺少局部可操作信号。规则 + 语义确认，修复提示携带症状类别与运行证据。

p.2 · §2 / 引言

结果与解释

  • 536 条源失败上，症状节点干预一次成功率 20.15%；完整无指导重试至多三次为 6.90%。
  • 节点选择与修复提示联合评估，不能将全部收益归给某个单独组件；成功仍由原生评估器判定。

p.6 · Table 4 / §5.4

具体变化｜作者方案

  • 控制粒度：固定可观测前缀，把干预后的变化留给实时执行；并不宣称完整系统逐位一致。
  • 证据组织：SymFail 把失败位置、类别与证据链接到事件图，支持源失败再现与修复比较。
  • 干预依据：C1–C4 是可观察症状，可用于修复而无需断定唯一根因。

实验补充：先分清两个问题

失败能否重现？在 536 条源失败上，完整重新执行的单次同类失败重现率为 67.97%，受控前缀回放为 80.78%（PDF p.5，Table 2）。能否修复？在同一批失败上，症状节点干预一次的成功率为 20.15%；无指导完整重试最多三次为 6.90%（PDF p.6，Table 4）。两者尝试次数和干预方式不同，不能简单视为同预算比较。

和 AG-Repair 的区别：SymTrace 主要固定干预前前缀、重新生成后缀，以控制实验；它不是一般意义上自动判断哪些干预后的下游节点可安全复用。方法成立还依赖外部环境能重置或隔离。
