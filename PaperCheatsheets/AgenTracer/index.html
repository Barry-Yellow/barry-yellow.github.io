多智能体故障归因：谁在哪一步导致任务失败？

AgenTracer: Who Is Inducing Failure in the LLM Agentic Systems?

Guibin Zhang、Junhao Wang、Junjie Chen 等 · NUS、CUHK、OPPO、NTU
arXiv v2 · 2025-09-04 · 正式发表状态未核验

一句话读懂

利用失败轨迹的反事实修正和成功轨迹的故障注入构造定位标签，再训练 8B 模型，预测责任智能体和关键步骤；其定位反馈还能用于后续自我改进。

原论文 Figure 2｜整个框架怎么运转

从左往右：多智能体系统与任务 → 成功/失败轨迹 → 注入故障或反事实修正 → 标注数据 → 多粒度奖励训练。点击图可放大。来源：PDF p.4，Fig.2。

问题｜看得到失败，找不到关键一步

最终答案错误，但长轨迹可能有多个看似可疑的步骤。单看最后错误或最后一个 agent，容易把症状当根因。

输入：任务与失败的多 agent 交互轨迹。输出：责任 agent 和决定性错误的步骤编号。PDF pp.3–4，§3

方案｜先构造数据，再训练定位器

失败轨迹：逐步提出局部纠正并回放，找最早可转为成功的步骤；成功轨迹：注入故障并验证是否导致失败。

把得到的 ⟨agent, step⟩ 标签用于训练模型；推理时直接读新失败轨迹，输出定位与解释。PDF pp.4–6，§4

图中两条标注路径：输入 → 验证 → 标签

原始轨迹具体操作纳入数据的条件得到什么
任务失败分析器结合错误反馈和参考答案，逐步生成局部修正；从该步重放后续。某步改后成功，取时间上最早的成功候选。原失败轨迹 + ⟨责任 agent, 步骤⟩
任务成功选中步骤并注入扰动，从该步骤继续运行。扰动后任务失败；注入位置作为构造标签。合成失败轨迹 + 注入 agent/步骤

PDF p.5 §4.1；p.6 Algorithm 1。合成标签是注入位置，不能由此自动证明真实系统只有一个根因。

从数据到定位结果｜训练、推理和证据

把“怎么找到错误”和“找到以后是否能帮助系统”分开读。

方法流程｜给没读过原文的人

阶段输入与处理产物及作用
1. 采集6 个多智能体框架运行编程、数学和通用 agent 任务，按任务评估器区分成功/失败轨迹。原始交互序列和成功/失败状态。
2. 标注失败轨迹逐步局部修正 + 回放；成功轨迹注入故障 + 回放。分析器/扰动模型使用 DeepSeek-R1。TracerTraj-2.5K：2,476 条轨迹—错误步骤对；并非全部为自然失败。
3. 训练以 Qwen3-8B 为基础，用 GRPO 生成多个候选定位并计算组内相对奖励。得到 AgenTracer-8B，学习输出理由及 agent/step。
4. 推理 / 反馈给模型一条新失败轨迹；定位时可设有/无参考答案 G；将解释反馈注入下一轮求解。责任 agent、关键步骤、诊断解释；后续改进由原任务系统执行。

PDF pp.4–7 §4–5；PDF p.16 Table 3（1288 + 630 + 558 = 2476）。训练与标注需参考答案，部署评估另有 w/o G 设置。

一个例子｜为什么要做反事实回放

帮助理解的虚构示例：搜索 agent 第 3 步误查到旧价格，写作 agent 第 6 步据此写出错误结论。

  1. 仅看最终答案，很容易把第 6 步当成唯一原因。
  2. 在第 3 步替换为正确价格，重放后续；如果任务变成功，它就是候选关键步骤。
  3. 逐步从早到晚尝试，取最早可改变结果的候选，标签为 ⟨搜索 agent, 3⟩。

注意：实际修正由分析器提出，并非数学意义上无误的 oracle；随机回放结果、可用参考答案和修正质量都影响标签。PDF p.5 §4.1

训练奖励与实际价值

奖励：格式正确才记分；agent 正确得离散奖励；步骤越接近标签，按高斯函数给更高分。λ=0.5，σ=1。PDF p.6 Eqs.11–12；p.7 §5.1

反馈实验：原系统失败后把定位解释放入下一轮，最多三轮。论文报告 MaAS + MATH-500 提升 14.21%，OWL + GAIA 提升 4.8%；这是任务准确率的作者报告，和定位准确率不是同一指标。PDF p.8 Fig.3；p.9 §5.3

与 AG-Repair 的关系及使用边界

AgenTracer 主要回答“哪个 agent 的哪一步可疑”，反馈驱动下一轮求解；AG-Repair 关注干预之后哪些下游结果还能安全复用。二者可衔接，但定位准确率不等于修复成功率。原文 Eq.4 的成功/失败标志与文字定义存在反向不一致，本表按 §3 文字和 Algorithm 1 解读；局部修正足以成功也不代表唯一根因。PDF pp.4–6
