单 agent 干预 → 成功局部输出 → 文本梯度 → 聚类/验证 → 新 prompt

拿一个输入走通方法

A 检索资料、B 汇总答案；某训练题失败，但只看最终错误无法确定该改 A 还是 B 的提示。

  1. 先只给靠后的 B 加训练 hint；若任务仍失败，这个干预不提供当前需要的成功纠正监督。
  2. 再试 A：若它补查正确来源后使整题成功，就把 A 记为该失败的更新目标。
  3. 固定 A 的局部输入，对比它原来的输出与 hint 后输出，提炼“先核对来源再提交”一类文本梯度。
  4. 把相似纠错方向聚成簇，提出新的长期 prompt；只有该簇和留出验证集都改善才提交。部署时使用新 prompt，不携带本题 hint。

关键设计为什么需要

干预回答“改谁有用”，原/修正输出差异回答“该怎样改”；语义聚合尝试将一次题目的经验推广成长期提示。

术语就地解释

hint：训练时帮助生成可成功行为的提示；文本梯度：自然语言的更新建议，不是参数梯度。

问题与输入 / 输出

输入

多智能体系统 Π、各 agent 提示 P、训练集和验证集、任务奖励函数；失败案例需要有 ground truth 或约束，供训练时构造干预 hint。

输出

更新后的 agent 提示集合 P*。提示优化阶段使用干预 hint，实际推理部署时不再注入 hint。

方法执行顺序

1
先收集失败样本

用当前提示 P 跑训练集，按奖励低于最大值的条件形成失败集合 F。

2
逐个干预，定位目标 agent

按执行顺序从后往前处理 agent；一次只给一个 agent 的 prompt 追加训练期 hint。能使该失败样本达到目标奖励的 agent 被记为该样本的目标 agent；仍未修复的样本继续向前测试。

3
生成 agent 级监督

对同一个局部输入，比较目标 agent 的原输出 ŷ 与注入 hint 后的修正输出 ỹ。二者差异近似隔离了该 agent 需要改变的行为。

4
提取并聚类文本梯度

梯度提取器根据 prompt、局部输入、原输出和修正输出生成单样本更新建议；聚合器按纠正模式聚类，并把每簇概括成一个通用梯度。

5
更新提示并双重验证

按较大语义簇优先提出候选 prompt；先要求该簇训练样本改善，再要求留出验证集也改善，否则丢弃候选。未被 hint 修好的样本在新一轮训练中重新尝试。

实验读数

任务效果

五个 MAS 基准上，GPT-5-mini 平均较无提示优化基线提升 +11.76 个百分点；Qwen3-8B 提升 +9.67 个百分点。报告值是三随机种子均值。

效率

GPT-5-mini 设置下平均优化时间比次快基线快 2.5×，平均 API 优化成本低 21.8%。

覆盖

HotpotQA、HoVer、PUPA、IFBench、MATH；涵盖多跳问答、事实核验、指令遵循、隐私委派与数学。

适用边界

边界：这是训练/优化阶段的多智能体 prompt repair，不是每次运行时自动回滚并修复轨迹。它依赖可用于构造 hint 的答案或约束；只有干预可修复的训练失败会生成当前轮的梯度信号，其他失败留到后续轮次。结果来自论文设定的五个基准与 GPT-5-mini、Qwen3-8B，不等于所有 agent 框架都能获得同等收益。

论文定位

多智能体 + 提示层长期修复。关键在于“干预确定 credit assignment → 结构化文本梯度 → 验证后提交 prompt 更新”。

一句话记忆：先用一次局部干预回答“改哪个 agent 的行为有用”，再把这个反事实差异变成可泛化的 prompt 更新。

核心思路

先通过逐 agent 的局部干预找出改谁能修好失败，再把同一输入下原/修正输出的差异转成可泛化的 prompt 更新。

已有做法与具体不足本文的对应设计

任务级反馈缺少中间 agent 监督把干预后输出作为局部伪标签。
随机拼接文本梯度会混杂不相关失败模式语义聚类后抽象共性更新方向。

创新点｜具体改了什么

  • 干预承担 credit assignment，并提供局部输出监督。
  • 梯度抽象与双重验证把案例级纠正转成提示级改进。
最吸引人的点 （整理者判断）

一次临时 hint 的作用不止救当前题，而是告诉系统“哪条长期指令该怎么改”。

创新点为贡献归纳，不作未经全面核验的首次声明；亮点为整理者判断。
