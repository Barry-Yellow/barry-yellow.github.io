单步候选替换 → 续程评价 → CRS 筛选 → 小编辑/审查 → 修复对

拿一个输入走通方法

agent 在第 i 步把单位换算错，后续答案随之出错；尝试对这一步做几个小修订。

  1. 保持 i 之前前缀，生成 K 个替换步骤，主设置 K=3。
  2. 每个候选替换 i 后重新处理后续；有执行器则执行，没有执行器的任务使用论文规定的预测式结果评价。
  3. 只要至少一个候选被判成功，CRS(i)=1；这是有限候选下的成功指示，不是“i 有 100% 概率为根因”。
  4. 在成功替换中选 token 位置匹配与长度惩罚意义下编辑更小者，经审查导出“原错误步骤—修正步骤”对。

关键设计为什么需要

同时保留失败与小幅成功修改，才能把调试产物做成步骤监督；预测评价和真实执行的证据强度必须分开。

术语就地解释

K：每步候选数；V：任务验证/预测评价；CRS：候选中是否存在成功替换的指示。

机制｜干预、筛选与证据边界

CRS 是有限候选下“至少一次替换成功”的指示量；失败的候选不足以证明该步骤绝非根因。p.4 · §4.1–4.2

五步流程

  1. 记录结构化轨迹：保留推理、工具调用和观测，确认最终失败。
  2. 逐步生成替换：为候选 sᵢ 生成 K 个小编辑，论文主设置 K=3。
  3. 评估替换：前缀保持不变，替换该步并重算其后续；有执行器时真实执行，否则采用预测结果。
  4. 保留成功小编辑：若至少一个候选通过验证，CRS(sᵢ)=1；在成功候选里按 token位置匹配与长度惩罚选编辑。
  5. 复核并导出：提出者、批评者和元批评者给出判断，结合置信度筛选；输出步骤级修复对。

p.4 · §4.1–4.2 p.5 · §4.3 / §5.3

创新点｜作者方案的具体变化

  • 用步骤干预产生归因信号，替代仅看日志提出原因。
  • 在成功候选中显式优化编辑最小性，并导出对照监督。
  • 加入多agent审查层，提高归因筛选的一致性。

p.4 · §4.1–4.2 p.5 · §4.3 / §5.3

最吸引人的点｜整理者判断

  • 一次调试既能生成修复，又能留下步骤级训练样本；这种监督价值依赖修复确实被可靠验证。

解读 · p.4 · §4.1–4.3

只需记住这个式子

CRS(sᵢ) = maxₖ 𝟙[ V(替换并续跑后的轨迹) = 1 ]
p.4 · §4.1–4.2
  • V 是任务验证；max 表示只要一个候选成功即记为1。这个分数本身不是失败因果概率。

p.4 · §4.1–4.2

实验说明与验证方式

  • 作者在四类任务展示了局部修复与对照监督价值；最终准确率并非总优于整体改写。
  • MBPP 有执行器；GSM8K 与两个浏览任务采用预测式结果评估。部分修复提示提供 gold 参考，作者另做去除参考的分析。
  • “最小”指步骤文本编辑小；顺序模型仍需处理该点之后的后续步骤，不等于独立分支复用。
