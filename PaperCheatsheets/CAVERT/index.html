任务合同 + 执行证据 → C/O/W/D → N、V 或 U

拿一个输入走通方法

合同要求截止前恢复 TLS 1.3，并持续有效到截止；日志里出现“已修复”消息，但还需看实际接收、执行和后续回滚。

  1. C 判断候选是否对应同一问题，O 确定谁在何时负有义务，D 检查有权者的有效履约。
  2. 若证据表明修复已生效且持续到截止，可判 N；不必先证明整个观察窗口完整。
  3. 若要判 V，必须确认相关通道和截止窗口足够可见，且履约缺失或无效；看到后来回滚且合同未满足，可支持违规。
  4. 若没有足够履约证据，又缺少认定违规所需的效果或窗口证据，保留 U，不把“没看到响应”推成“没有响应”。

关键设计为什么需要

N/V/U 区别是证据是否足以判定，不只是模型分数高低；同一句“已修复”不能替代行动效果与时限证据。

术语就地解释

C：候选成立；O：义务；W：观察窗口证书；D：有效履约；N 无违规，V 违规，U 无法判定。

一句话读懂

把任务义务与执行证据一起建模：先判断记录是否足以证明履约，再输出无违规／违规／无法判定；必要时在写入提交前拦截旧状态依赖。

原图 Fig.5｜CAVERT 总体流程 · PDF p.6

原图裁切。左：日志与公开合同 → 证据适配；右上：合同判定；右下：诊断和可选读后再写控制。p.6 · Fig.5

任务与输入输出

  • 输入：任务开始前固定的公开合同 P、消息／记忆操作／工具结果、接收与覆盖元数据。
  • 中间结果：带源事件链接的证据 T，以及每个候选问题的 C/O/W/D 检查状态。
  • 输出：N/V/U、责任 agent、缺失证据和来源；可选输出阻断与刷新建议。

p.6 · §4 · Fig.5

中文标签与阅读顺序

  • 读图顺序：Evidence Recovery（证据恢复）→ Contract verdict（义务判定）→ Auditable diagnosis（可审计诊断）→ Read-before-write（先读后写）。
  • 术语：Candidate=候选问题；Obligation=义务；Window=观察窗口；Discharge=已履约。

p.6 · §4 · Fig.5

方法：按执行顺序读

  1. 范围过滤：选出与同一实体、属性、作用域相关的消息、记忆和工具记录。
  2. 因果状态恢复：把更新接收者、使用该状态的动作、响应效果连起来；保留原事件链接，无法确认的关系置 unknown。
  3. 建立检查状态：C 判问题是否成立；O 判责任、激活与截止时间；W 判窗口是否充分观测；D 判响应是否由授权者按时完成且持续有效。
  4. 确定性判定：按原 Fig.3 输出 N/V/U；共享义务、兼容语义键且有已验证连接路径时才合并 findings。
  5. 可选干预：未提交写操作依赖已过期状态时阻断，要求通过公开读刷新，再重新提出动作。

p.6 · §4 · Fig.5

前作不足 → 本文设计

相关做法的不足本文如何处理
记忆治理（如 MemTX）主要规定记录何时可用把接收、动作依赖、授权和截止时有效性纳入履约证据。
日志诊断或二元检查可能把未观察到的响应当成未响应增加 U（无法判定），显式检查相关通道与时间窗口覆盖。
看到纠正消息不等于下游行动已改变依赖 finding 驱动提交前读刷新，并用后续执行评价恢复。

原图 Fig.3｜三值决策树 · PDF p.5

原图裁切。先检查问题与义务；已履约可先返回 N。要认定未履约，则需完整相关观察窗口。p.5 · Fig.3 · Eq.1

判断依据与关键细节

  • C：仅比较语义键相同的状态；旧版本在合同允许固定版本时不自动违规。
  • O：义务已履行可先得到 N；待截止或政策冲突通常保留 U。
  • W：覆盖相关通道与因果依赖、顺序可靠、可见性成立、截止已知且日志延伸到截止。
  • D：响应须有责任／授权者、正确义务和作用域、有效时限、成功效果及截止时持续有效。

p.4 · §3.1

相对近邻的变化

  • 判断对象从“记录是否一致”推进到“特定义务是否履行，且证据是否足够”。
  • 以 C/O/W/D 和三值规则连接 LLM 语义提取与确定性裁决；U 表示证据不足，并非低置信度。
  • 通过移除／恢复同一执行对中的证据检验可判定性，再单独评价诊断与干预。

p.6 · §4 · Fig.5

最值得记住

  • 最吸引人的点（整理者判断）：把“无法判断”变成有条件的正式输出，避免模型替缺失的执行关系作结论。

解读 · p.5 · §3.2

结果与适用边界

  • 作者结果：在 720 次执行上，CAVERT 诊断准确率 87.1%，合同提示 LLM 为 80.6%；同门控条件下，四个环境均改善恢复。
  • 边界：LLM 恢复的关系仍会出错；门控限于可无副作用拒绝的未提交写操作，已生效操作需另行补偿。
