MASC 在每步输出下游传播前做异常检测；检测到偏离正常轨迹的输出时，调用纠正 agent 改写当前步骤。

历史预测 x̂ + 实际 x → 异常分 → 阈值 → 原消息/纠正消息

拿一个输入走通方法

检索结果显示共有 3 项，但当前 agent 写成 30 项，并即将把该消息传给下游。

  1. 检测器仅凭任务与之前历史预测当前输出应有的表示 x̂；实际当前输出编码为 x。
  2. 计算重建偏差与正常原型偏差，组合成 s(t)，再与阈值比较。
  3. 若判异常，Corrector 读取当前输出并修订；写入下游历史的是修订后的消息，而不是异常分本身。
  4. 若未触发则放行原输出；这个语义错误是否一定使向量分数超阈值并无保证。

关键设计为什么需要

表示重建给检测器一个“正常会怎样”的参照，原型帮助历史较少时稳定预测；两者都不能替代真实语义验证。

术语就地解释

x：实际输出向量；x̂：预测向量；p：正常原型；α、β：两种偏差的权重，最终分用于是否调用纠正者。

要解决什么？输入与输出

输入

当前 agent 的输出 Oₜ、任务 query Q、此前交互历史 Hₜ₋₁；训练阶段使用正常轨迹，不需要逐步错误标签。

输出

通过检测的原输出，或经 correction agent 改写后的输出 Õₜ；将该结果写入下一步历史。

方法怎样运行

1
用正常轨迹训练

把 query、历史和每步输出编码为向量；方法用正常轨迹学习预测下一步表示的模型，并学习正常行为原型 p。

2
预测当前步

执行到第 t 步时，仅依据 query 与 t−1 之前的历史，重建当前输出应有的表示 x̂ₜ。

3
计算异常分

4
触发纠正 agent

若分数超过设定阈值，把当前 acting agent 的输出交给 Corrector 修订；否则原样通过。

5
更新后续上下文

用通过/修正后的结果更新 Hₜ，再继续多智能体执行；错误在向下游传播前被处理。

s(t) = α · ||x̂ₜ − xₜ||²₂ + β · [1 − cos(x̂ₜ, p)]
xₜ：实际当前步表示；x̂ₜ：用此前历史预测的表示；p：正常步骤原型；α、β：两项权重。

边界与阅读结论

理解边界：它是在线检测与纠错，不是失败后回放/搜索修复。论文结果分别包含检测指标（AUC-ROC）和任务准确率，不能把它们直接读成“失败恢复率”。方法训练依赖正常轨迹，部署还需设置异常阈值；后两点是根据机制得到的使用条件。

论文定位

多智能体运行中纠错。比事后归因更早介入，核心价值在于把可疑输出挡在下游 agent 之前。

一句话记忆：记住：预测“当前这一步按正常历史应该长什么样”，再把偏离程度转成异常分数。

结果补充：两种实验不要混读

检测：在 Who&When 手工数据、无真实答案（w/o GT）条件下，LLaMA-3.1-8B 配置的 MASC AUC-ROC 为 77.84%，表中对应的监督 BERT 分类器为 72.86%（PDF p.7，Table 1）。AUC 评价异常步与正常步的排序，不是最终任务成功率。

端到端任务：GSM8K 上，三种网络拓扑（Chain、Complete、Random）的 MASC 平均准确率为 89.56%，相同拓扑未加检测纠错的平均为 87.10%，相差 2.46 个百分点（PDF p.8，Table 3）。此数是三个拓扑在 GSM8K 上的平均，不是六个基准的平均。

和 AG-Repair 的区别：MASC 检测当前输出并在传播前纠正，AG-Repair 面向失败后已有轨迹的修复及下游复用；MASC 并不回答修改过去步骤后如何安全复用已生成的下游结果。
