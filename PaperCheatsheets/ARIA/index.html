执行验证修复对 → 学检查/改写 → 前缀门控 → 替换续程

拿一个输入走通方法

搜索任务执行到一半，当前前缀显示 agent 已忽略日期约束；宿主能够保留前缀并替换后续执行。

  1. 离线对相近失败生成诊断 d、保留切点 k 与替换事件 e；只有原续程失败而修改续程成功的配对才成为有效修复监督。
  2. SFT 学结构化输出和检查，DPO 偏好经验证的续程，GRPO 再用执行结果优化修复与门控；这是学习阶段。
  3. 运行时先读可见前缀判断是否应介入；若不应介入则继续原执行，不必每一步都搜索多个修复。
  4. 若介入，保留到 k 的前缀，丢弃原后缀并接入 e 继续；任务最终是否成功仍须宿主执行与评价。

关键设计为什么需要

训练把过去昂贵的试改经验压进模型；门控避免把原本可成功的运行也强行改写。预测出的诊断不自动成为唯一因果解释。

术语就地解释

SFT：监督学习格式与行为；DPO：偏好优化；GRPO：利用执行反馈的强化学习；k 对应被保留的切点。

问题与输入输出

  • 问题：事后定位只说明哪里错；每次在线搜索与重跑代价高。运行中还必须判断当前前缀是否已需要修复。
  • 输入：公开任务与约束、MAS可见执行前缀；事后模式可额外拿到评价失败反馈。
  • 输出：检查门控决定介入时，给出诊断 d、切点 k、替换事件 e；宿主保留有效前缀后继续执行。

p.1 · 摘要 / §1

图旁中文对照 / 阅读顺序

  • 左 Dataset：4种MAS×6个benchmark×8种宿主模型收集>24,000轨迹，保留3,953对已执行验证修复。
  • 上 Training：SFT学结构与检查→DPO偏好有效修复/可迁移诊断→GRPO用真实执行反馈优化修复和门控。
  • 下 Runtime：监测部分轨迹→需介入才Inspect/Amend；保留有效前缀并续跑，另支持完整失败轨迹的事后修复。

p.4 · Figure 2

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 选数据来源：对每个MAS×任务集固定单元，估计原成功率a与失败条件下修复率r，按S=(1−a)r选模型，追求每次执行获得更多可验证修复。p.3 · §2.1；p.4
  2. 形成监督：定位错误、给修复归因、生成(d,k,e)；分别执行原样与修改续程，仅原样失败且修改成功才收为正修复对。p.3 · §2.1；p.4
  3. SFT→DPO：先学JSON修复格式与前缀检查；再偏好已验证修复而非原失败后缀，并用相关样本上的修复预测增益挑诊断。p.4 · §2.1–2.2；p.5
  4. GRPO：对当前模型提出的修复真实续跑，以任务接受−损害−开销为奖励；诊断还看跨配置相关事件的执行收益，门控按匹配种子任务差值优化。p.5 · §2.2
  5. 运行时改写：门控读取前缀，必要时输出切点与替换事件；切点本身保留，后缀丢弃，接入新续程继续执行；前提是宿主支持续程替换。p.18 · B.3 / Eq.8

差异、证据边界与必读前作

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.16 · Appendix A；p.10–15 References

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
AgentRx / Who&When式诊断：定位责任步骤，但不直接给可执行修复或运行时介入决定。训练模型联合输出诊断、切点、替换续程，并增加前缀级检查门控。
CausalFlow / DoVer：部署时逐例生成干预并重执行验证，成本随搜索增长。跨配置汇总已验证修复作训练，让在线预测复用过去搜索得到的策略。
只按失败频率挑来源：失败多不代表可修，强模型又可能几乎不失败。用(1−原成功率)×条件修复率衡量监督产出，并以成对执行排除偶然成功。

p.16 · Appendix A；p.10–15 References

创新差异｜作者主张，按机制归纳

  • 数据：由执行结果支持的失败—修复对，显式标出改什么、在哪里切、如何续跑。
  • 三阶段后训练：结构监督→结果锚定偏好→执行与跨配置反馈，诊断和修复分别获信用。
  • 联合选择：运行时检查门控与续程生成共享模型，训练中显式惩罚损害原本能成功的任务。

p.4 · §2.1–2.2；p.5

结果与使用边界

  • 作者报告：Qwen2.5-7B事后失败集SR35.3%、EB2.00；运行时全任务SR21.4%、HIR2.00%、EB1.00（分母不同，不可直接比较）。
  • 验证边界：成对续跑证明该修改恢复任务，不证明诊断是唯一因果解释；DPO诊断增益是似然代理，GRPO才用执行反馈。
  • 接口限制：需要可见事件与续程替换；默认只保留首4+末60事件，定位不能认证被省略部分中的最早错误。结果不等于任意MAS均有同等恢复率。

p.7 · Tables 1–2；p.8–9

最吸引人的点｜整理者判断

  • 数据采集本身按“每次执行能产出多少可修失败”优化，避免只收最弱模型的大量无用失败。

解读 · p.4 · §2.1–2.2；p.5

重要参考｜题名、官方链接与摘要已核对

  • DoVer: Intervention-Driven Auto Debugging for LLM Multi-Agent Systems：摘要核对：以定点干预和重执行验证故障假设；ARIA把此类验证结果汇总为可学习策略。
  • AgentRx: Diagnosing AI Agent Failures from Execution Trajectories：摘要核对：按执行轨迹中的约束违例定位关键失败步骤；提供诊断型对照。
  • CausalFlow: Causal Attribution and Counterfactual Repair for LLM Agent Failures：摘要核对：对单代理轨迹作因果归因与反事实修复；ARIA侧重跨MAS监督与运行时学习。
  • Direct Preference Optimization: Your Language Model is Secretly a Reward Model：摘要核对：直接从偏好优化策略；是ARIA第二阶段偏好训练的方法基础。
