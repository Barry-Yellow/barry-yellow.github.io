把每次能力匹配的同伴评审同时用于两件事：任务内纠错，跨任务检测持续降质；被隔离者通过恢复探针获得重新入网的证据。

原输出评审 → 当前接管；原评分历史 → 健康状态 → 路由/恢复探针

拿一个输入走通方法

节点 A 格式正常但数学能力持续退化；正常邻居 B 能评审并修正 A 的回答。

  1. 快速层对 A 的原输出评分；低分等条件触发委员会复评，并可能由 Takeover 用修正内容替换当前任务结果。
  2. 当前任务可因此继续，但慢速层仍记 A 原输出的分数，不能把 B 的修正后高分算给 A。
  3. 按相同任务类别/能力比较邻居基线，积累足够匹配观察并平滑短缺，才逐级进入 watched/isolated。
  4. 隔离后保留转发，安排资格探针；经评审证明恢复后逐步回归，不因永远绕开而永无恢复证据。

关键设计为什么需要

当前内容质量与长期生产者健康使用同一批证据，却必须保留归属。一次低分不够判持续灰故障，接管也不代表原节点恢复。

术语就地解释

灰故障：接口还正常、质量持续下降；watched：加强评审；isolated：暂时移除能力资格而非断开全部消息。

原图裁切：先读 (a) 能力互补的任务路由，再读 (b) 快速评审/接管与慢速隔离/恢复，最后读 (c) 强弱模型后端如何模拟能力和灰故障。p.2 · Fig.1

输入 → 输出

  • 输入：仅能与邻居通信的 agent 网络、各节点能力集 Kᵢ、连续任务及任务类别；真实健康状态不可见。
  • 输出：经过评审的中间产物/答案，以及节点 normal、watched、isolated 状态和更新后的局部路由。
  • 灰故障：节点仍通信且输出格式正常，但相对名义能力持续降质；一次答错并不足以判为灰故障。

p.5 · §4.1–4.2

原图标签

  • Handoff＝能力不匹配时只转交；Contribute＝做匹配部分；Finalize＝补全剩余能力并收尾。
  • Takeover＝评审者修正结果替换原输出；Watched＝继续路由但强制委员会评审；Isolated＝能力暂设为空，只保留转发。

p.2 · Fig.1

方法流程｜5 步

  1. 匹配路由：推断剩余需求能力，按本节点交集决定转交、贡献或收尾；用邻居距离找到最近能力节点。
  2. 快速打分：正常且覆盖所需能力的邻居独立评三次取中位数；低分、高分歧、watched 或恢复探针升级到两人委员会。
  3. 当前纠错：委员会交换理由后复评；最终低分触发 Takeover，生成并汇总修正候选，替换进入任务上下文的原输出。
  4. 慢速检测：原生产者保留原评分；按同任务类别/能力与正常邻居比较短缺，跨任务平滑并用邻居低侧离散度归一化。
  5. 隔离恢复：不足证据不改状态；持续越界逐级 watched/isolated 并改路由；周期资格探针经委员会复评后逐级返回。

闭环｜纠错评分继续服务于路由与恢复

接管后的高质量输出用于当前任务，接管前生产者的分数用于健康判断；否则纠错会把原生产者的持续退化掩盖掉。p.6 · §4.2.1–4.2.2（续 p.7）

前作不足 → 本文设计

前作或常见做法的不足本文对应设计
自一致性、辩论与聚合主要提升当前任务输出。把原生产者评分跨任务积累，识别持续降质并改变后续资格。
Symphony/RAPS 一类历史路由需等证据积累。在慢速判定前，快速层先审查并替换当前低质量输出。
节点被持续绕过后，不再产生恢复证据。隔离节点保留消息转发，以受控能力匹配探针复评并重新加入。

p.3 · §2 / 引言

慢速层的判断具体是什么

  • 短缺 = 同类别/能力正常邻居近期均分 − 当前原输出分数；按 (任务类别,能力) 维护滑动均值。
  • 用邻居均值短缺的中位数和低四分位差归一化；避免未发现的降质节点把高尾基准抬高。
  • 不足三个匹配观察保持状态；超过较低阈值 watched，连续两次超过较高阈值 isolated。探针先回 watched，再经后续证据回 normal。

p.6 · §4.2.1–4.2.2（续 p.7）

具体变化｜作者方案

  • 双时间尺度共用评审：快速层保护内容，慢速层保护生产者选择与恢复。p.6 · §4.2.1–4.2.2（续 p.7）
  • 检测基准条件化：匹配任务类别和能力，再做同伴相对归一化，减少固定绝对分数跨后端失效。p.6 · §4.2.1–4.2.2（续 p.7）
  • 评测设计：名义能力由强/弱模型后端实现，退化将强后端换成弱后端，同时保持通信接口。p.7 · §5

最吸引人的点

  • 整理者判断：纠错和健康检测共享证据但保留各自归属，兼顾立即补救与长期淘汰，还给恢复留了入口。
