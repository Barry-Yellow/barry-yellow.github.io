错源 → 影响候选 → 独立支持筛选 → 清理状态 → 必要步骤重放

拿一个输入走通方法

错误记忆 m 说商品有货；它产生计划 p 和订单动作 a。另一个结论 c 虽引用过 m，却也有独立可信的新查询支撑。

  1. 从已知错源 m 沿真实数据依赖求候选影响集；不能把 m 后所有时间步骤都视作污染。
  2. 对候选逐项检查完整结论/决策是否有影响集之外的充分可信支撑；c 若确有这种支撑，可保留。
  3. 删除错源、隔离无支撑派生记忆，使 p/a 等无支撑轨迹输出失效，不允许继续当证据。
  4. 在失效项中仅选通向最终答案且补齐执行前提的步骤重算；工具观察由重跑动作产生，最终答案重新生成。

关键设计为什么需要

失效集合回答“哪些旧内容不可信”，重放集合回答“为新答案必须再算哪些”。保留和重放判据都依赖显式溯源，不能靠受影响节点相互证明。

术语就地解释

独立支持：来自错源及初始影响集之外的充分证据；CHAIN 时间边本身不传播污染。

问题与输入输出

  • 问题：只删错记忆，已经生成的错误主张、工具结果及派生记忆仍可能继续影响后续会话。
  • 输入：会话 U、活动记忆 M、失败轨迹 T、上游已诊断的错误记忆 F，以及工具与运行时溯源。
  • 输出：新答案、修复轨迹 T′、修复后的活动记忆 M′；错误诊断本身不在本文范围。

p.1 · 摘要 / §1

图旁中文对照 / 阅读顺序

  • ①–② Construction / Tracing：建图→沿真实数据流取候选影响集；时间先后 CHAIN 不作污染传播边。
  • ③ Support：候选外仍有充分可信证据→保留；否则→交给回滚规划器。
  • ④–⑤ Plan / Replay：持久记忆先删除/隔离；轨迹先失效，再按答案相关性与执行前提选重放集合。

p.3 · Figure 2

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 建图：用户、记忆及读取/主张/计划/动作/观察/写入分别成节点；从运行时 used_ids 等字段确定有类型的来源→依赖边。p.3 · §3.2–3.6
  2. 追踪：从错误记录或其失败更新/产生步骤出发，仅沿显式传播边得到 A₀；不用整段时间后缀。p.3 · §3.2–3.6
  3. 判断保留：逐个检查候选的完整内容或决策，是否由 F∪A₀ 外的可信充分证据支持；不能用受影响节点相互担保。p.4 · §3.4
  4. 制定计划：删除 F，隔离无支撑派生记忆，令无支撑轨迹输出失效；找仍通向最终答案的节点，再补齐执行前提闭包。p.4 · §3.5
  5. 执行：先修活动记忆，再按原轨迹顺序重算所选步骤；安全输出作固定上下文，工具观察由其动作重新产生，最终答案总是重生。p.5 · §3.6

差异、证据边界与必读前作

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.2 · §2 / §3

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
记忆审计 / 删除：主要处理错源，不能自动撤销已经传播的状态。图同时覆盖记忆生命周期与执行轨迹，把无支撑后代从活动状态中清走。
MemoRepair：主要处理存储中的派生物撤回与重新发布。扩展到主张、计划、工具动作/观察和最终答案，并由答案相关性决定重放。
反思或因果定位：修回答或找错因，不等于完成记忆状态清理。把清理计划与选择性执行绑定，并保留候选外充分支撑的有效结果。

p.2 · §2 / §3

创新差异｜作者主张，按机制归纳

  • 修复对象：同一次计划同时处理持久记忆与异构执行轨迹，而不是只修改一个回答。
  • 保留条件：可达仅表示候选影响；有独立充分支撑时仍允许复用。
  • 重放边界：无支撑节点全部失效，但只有答案相关计算及其必要前提被重放。

p.3 · §3.2–3.6

结果与使用边界

  • 作者报告：150例受控集恢复85.3%（最佳对照77.3%）；重放12.3%，平均5.70次LLM调用。
  • 取舍：本方法复发率26.6%，并非最低；去掉选择性重放可降至7.1%，但调用增至24.01。
  • 限制：假设已知错源且运行时溯源充分；外部不可逆操作不能靠此回滚，须可重置/幂等/补偿接口。
