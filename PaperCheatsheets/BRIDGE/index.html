拿一个输入走通方法

上游已查到证据 e，下游撰写者收到结论却没收到 e，公开依赖图显示该必需信息未送达。

  1. 把“e 未交给指定接收者”定位成未满足前沿；若 e 在公开历史中可得，INTEGRATE 可将其编入交接消息。
  2. 若证据只在上游私有状态，不能假装检索到了，需考虑 ASK；动作还必须符合角色、预算等前置条件。
  3. 从冻结校准统计估帮助、损害、无变化及成本；正净效用、损害率和样本量都过门槛，才暂存执行。
  4. 生成新消息后检查公开图的后置条件：目标缺口是否补齐、证据作用域是否正确、旧依赖是否未破坏；失败就撤回本地暂存，发送原消息。

关键设计为什么需要

“值得试”与“生成后允许发”是两道门。局部回滚只撤销未放行消息和本地图状态，不撤销外部世界副作用。

术语就地解释

frontier：最早未满足的公开依赖；postcondition：执行该修复后必须能观察到的结果条件。

问题与输入输出

  • 问题：每个智能体说得合理，也可能因交接缺证据、送错人、收到未用而整体失败；随意重提示还可能破坏正确中间状态。
  • 输入：原交接消息、公开消息/工具历史、任务契约（义务/角色/约束）、冻结的校准统计及预算。
  • 输出：验证后的修复消息；无缺口、无合格动作或验证失败时，直接放行原消息。

p.1 · 摘要；p.2 §1

图旁中文对照 / 阅读顺序

  • 下层 HandoffProbe：故障注入→相同前缀分别原样/修复续跑→外部验证→冻结收益、损害、无变化率。
  • 上层 Frontier：图中最早未满足依赖；ASK问发送者，INTEGRATE把已有证据编入消息，另可VERIFY/DECOMPOSE/RETRIEVE。
  • Utility gate → Verified execution：先估净收益，再看图状态变化是否真正满足后置条件；失败恢复本地图快照。

p.3 · Figure 1

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 更新图并找缺口：按契约记录事实的产生/送达/消费；识别已送未用、从未观察到、或送错目标角色的事实，优先最早未满足依赖。p.5 · §3.2 / Table 1
  2. 枚举可行动作：检查前置事实、执行角色能力和预算；私有上游信息不可直接RETRIEVE，只能ASK。p.5 · §3.2 / Table 1
  3. 离线校准：固定同一故障前缀，分别运行原始与修复续程；确定性任务验证器把结果标为helped/harmed/neutral，并统计成本。p.5 · §3.3
  4. 门控选择：效用=帮助收益−无变化干扰−损害−成本；仅接受效用>0、经验损害率≤阈值、历史样本数足够的动作，择最高者。p.6 · §3.4–3.5 / Algorithm 1
  5. 暂存后验证：检查目标前沿已解决、证据在作用域、原依赖未被破坏；通过才发新消息，否则撤销本地暂存并发原消息。p.6 · §3.4–3.5 / Algorithm 1

差异、证据边界与必读前作

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.3 · §2；p.9–10 References

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
MOC / Routed Graph Handoff：优化多跳信息组织或消息格式，不等于验证某项必需证据已经被正确消费。用契约事实的生产、路由、消费关系显式定位交接缺口。
AgentAsk / Self-Refine：问询、重写可执行，但并非每次介入都会提高任务成功率。HandoffProbe测成对续程，按净收益/损害/样本量选择性介入。
只生成“看似更好”的消息：无法保证补充真的到达目标，也可能损坏既有依赖。修复在暂存区执行，后置条件验证后才释放；失败回到原交接消息。

p.3 · §2；p.9–10 References

创新差异｜作者主张，按机制归纳

  • 证据边界：把交接失败约束为公开可观察的事实依赖缺口。
  • 选择性：把是否值得介入变成按动作×缺口统计的经验决策，而非见错就问。
  • 提交机制：图状态差分满足声明后置条件才放行；回滚范围明确为本地图和未发消息。

p.4 · §3.1–3.5；p.5–6

结果与使用边界

  • 作者报告：SILO-BENCH上DeepSeek原始成功63.3%→75.6%；GPT为68.9%→77.8%，后者额外token约2.0%。
  • 可迁移边界：校准先验可冻结跨环境，但作者说明效用仍依赖模型，需要骨干专属校准。
  • 机制限制：完全隐藏在不透明智能体内部的通信错误难以处理；本地消息回滚不代表撤销外部世界副作用。
