错误表现节点 → 有界上游候选 → 特征评分 → 可疑动作排名

拿一个输入走通方法

动作 a 产生错误数据，消息 b 传给另一个 agent，最后动作 c 因消费它而报错。

  1. 从 c 这个已知错误表现点反向 BFS，沿顺序、通信与数据依赖找到深度 d 内的候选，可能同时含 a、b、c。
  2. 对候选计算位置、结构、内容、流与置信五组归一化特征。
  3. 按论文固定加权式排序，返回可疑动作；回溯路径本身不决定 a 一定排首。
  4. 若日志未记录 a→b 的数据关系，a 可能无法进入可达候选；方法不在此执行修复来验证遗漏或排名。

关键设计为什么需要

候选资格来自图关系，名次来自特征分数；这是轻量事后定位，不能把“因果图”的名称当成已完成因果干预。

术语就地解释

BFS：逐层图搜索；d：回溯深度上限；五组线性分数用于排序，而不是根因概率。

帮助理解的示例：为解释原文机制而简化，不是论文案例、实测结果或成功保证。方法依据：PDF p.3、PDF p.4。

原图裁切 · PDF p.2。左→右读：多智能体执行日志、三类依赖图、错误节点反向BFS、根因排名；保留箭头和图例，点击可放大。p.2 · Figure 1 / §2

问题与输入输出

  • 问题：报错位置可能只是症状；更早的计划、数据或消息错误已沿智能体链传播。
  • 输入：完整失败执行日志、错误表现节点 v_error、反向搜索深度上限 d。
  • 输出：上游候选集 C 及按分数排列的可疑动作；动作包括工具调用、消息和决策。

p.3 · §3.1–3.3 / Algorithm 1

图旁中文对照

  • Causal Graph：动作节点与依赖边。
  • Backward Tracing：从错误节点找父节点，不把“最后报错”直接当根因。
  • Root Cause Ranking：候选资格靠可达性，最终顺序靠特征分数。

p.2 · Figure 1 / §2

机制顺序｜先定候选范围，再排序

  1. 建图：同一智能体相邻动作连 sequential；跨智能体消息发送→接收连 communication；变量引用跟踪把数据生产→消费连 data dependency。p.3 · §3.1–3.3 / Algorithm 1
  2. 反向BFS：C初始含错误节点；逐层加入未访问父节点，最多走 d 层。得到“可能相关”的祖先集合。p.3 · §3.1–3.3 / Algorithm 1
  3. 提特征：五组共17项；每项在节点间min-max归一化，组内取平均。位置含相对序号、距错误节点距离、深度比、反向位置；结构含入/出度、中介中心性、后代可达率。p.4 · §3.4 / Table 1
  4. 加权排名：score = 0.70P + 0.20S + 0.05C + 0.03F + 0.02E。内容C含错误词/不确定词/长度异常/关键词密度；流F含智能体切换/角色权重/消息类型；置信E含声明置信度/模糊措辞。按分数排序。p.4 · §3.4 / Table 1

前作对照、贡献与证据边界

根因在定义上是“修正后可阻止失败的最早决策”；本文用图与特征近似定位，没有给出真实修复、重放或修复后复用判据。p.3 · §3.1–3.3 / Algorithm 1 解读 · p.3 · §3；p.7 §6–7

前作的具体不足 → 本文设计（按作者论述归纳）

所指方法 / 不足本文设计 / 作用
AutoGen、MetaGPT等协作框架：主要组织协作，本文认为调试仍依赖人工读日志。把跨智能体动作、消息与数据流显式建图，提供独立事后诊断层。
LLM自调试/全文分析：需推理调用，可能把下游错误表现当源头。从已知错误节点限制上游候选，再用固定特征排名；调试时不用LLM。
传统分布式追踪/云RCA：请求元数据或服务故障结构与智能体工作流不同。适配到动作、语义消息与变量数据依赖；此处为作者定位，并非穷尽比较。

p.2 · Figure 1 / §2

贡献差异｜作者主张，按机制归纳

  • 对象：把执行动作而非模型内部神经元作为可解释诊断单元。
  • 组合：三类边 + 有界反向BFS + 五组特征线性排序形成轻量定位器。
  • 证据：提供带已知注错点的合成轨迹与基线对比。

p.2 · §1–2；p.3–4 §3

实验一句与局限

  • 作者报告：550例/10领域、每条8–15动作；Hit@1=94.9%、Hit@3=98.4%，平均0.12秒。p.4 · §4；p.5 §5.3 p.5 · §5.3 / Table 3 p.7 · §5.7 / §6–7
  • 适用边界：合成、单根因且假设日志准确；生产轨迹验证、多根因仍待完成。位置单组已达87.3%，总体成绩不能直接外推长轨迹。p.7 · §5.7 / §6–7 p.6 · Table 4

最值得记住｜整理者判断

  • “反向可达”给候选资格，“位置与结构分数”才给最终名次；这里的因果图是日志依赖表示，排序本身未执行因果干预。

解读 · p.3 · §3；p.7 §6–7

选题对照（整理者判断）

  • 与AG-Repair重合：失败轨迹→typed图→根因定位。可借鉴显式消息/变量边与快速候选筛选。
  • 可继续聚焦：修复改变上游后，旧下游结果是否仍有效；隐式依赖如何暴露；哪些非连续结果可复用。本文没有污染撤销、checkpoint或选择重执行方案。
