Self-Refine：用自反馈迭代改写输出

Self-Refine: Iterative Refinement with Self-Feedback

Aman Madaan、Niket Tandon、Prakhar Gupta 等 16 位作者
CMU、AI2、University of Washington、NVIDIA、UC San Diego、Google Research
初次提交 2023-03-30；所用 v2：2023-05-25
NeurIPS 2023 主会论文；本笔记图表/数字依据 arXiv v2，不混用版本。

一句话：同一个 LLM 先写初稿，再指出初稿中具体可改之处，再把这些反馈落实成新稿；保留历次输出与反馈，重复到任务停止条件满足。

改变的是提示上下文和候选输出，不更新模型权重。它是输出改写方法，不是多智能体责任归因或环境回滚算法。

原 Fig.1｜同一模型，三个提示角色

什么问题，为什么不只“一次生成”？

写对话、改代码可读性或满足一组词汇约束时，“生成得通顺”不代表多项要求都达标。初稿可能有用，但模型当场就能看出局部改进方向，未必需要为每个领域训练一个专用改写器。

输入：任务 x、固定模型 M、三个任务专用提示；中间状态：候选 y 与文字反馈 fb 的历史；输出：停止时保留的候选文本/代码。PDF p.2 · §1–2PDF p.3 · Algorithm 1

按顺序走通：每一步传什么

  1. Generate：用 pgen 和 x 生成 y₀。pgen 可含任务输入—输出示范。
  2. Feedback：同一 M 读 pfb、x 和当前 yₜ，生成 fbₜ。要求具体指出哪里有问题，并给出可执行的修改方向。
  3. Stop：用反馈中的停止指示/分数或轮次预算判断是否结束；停止条件按任务定义。
  4. Refine：未停则把 x、历次候选与反馈连同 prefine 交给 M，得到 yₜ₊₁，再回到 Feedback。
y₀ = M(pgen ∥ x)
fbₜ = M(pfb ∥ x ∥ yₜ)
yₜ₊₁ = M(prefine ∥ x ∥ y₀ ∥ fb₀ ∥ … ∥ yₜ ∥ fbₜ)

∥ 表示拼接上下文。三个 p 是提示，不是三个训练出的模型；t 是迭代编号。式 3 给单轮简式，式 4 与主算法明确带历史。PDF p.3 · Eqs.1–2 / Algorithm 1PDF p.4 · Eqs.3–4

最值得记住的设计（整理者判断）：把“再做得好一点”拆成先找具体改动方向、再执行改动。这里“改哪里、怎么改”的中间文本才是关键接口；同一模型能生成有用评价，不等于它能可靠识别所有事实或推理错误。

原文代码例：反馈究竟改变了什么

x：计算 1 到 N 的和。y₀：循环累加，功能正确但耗时随 N 增长。fb₀：指出遍历过慢，并建议用等差求和公式。y₁：直接返回 n(n+1)//2。

初稿：for i in range(n+1): res += i
反馈：指出 for 循环瓶颈，并建议求和公式
改稿：return (n*(n+1))//2

这不是“发现错误答案后重跑环境”，而是对一个已经功能正确的程序优化实现。若反馈只说“更高效”，缺少瓶颈和操作方向，refiner 得到的指导就更弱。PDF p.3 · Fig.2(d–f)PDF p.4 · actionable / specific

提示如何规定反馈，而不是凭空自省

  • 生成提示 pgen：输入—输出示范，教模型怎样完成任务。
  • 反馈提示 pfb：输入—输出—反馈三元示范，教模型指出具体片段与改进动作；可按多个质量维度评价。
  • 改写提示 prefine：输入—输出—反馈—改稿四元示范，示范如何落实建议。

因此“不额外训练”不等于完全没有人为任务设计或示范监督。few-shot 示例在上下文里起作用，模型参数保持不变。PDF p.3 · §2 提示定义PDF p.4 · REFINE / Iterating

历史和停止条件有何作用

历史保留过去试过的稿子与反馈，帮助避免再次犯同样问题；它不是独立的长期知识库或跨任务训练。代价是提示随迭代变长，且每轮通常多一次反馈和一次改写调用。

主实验最多 4 次迭代；可按轮次或模型输出的停止指标结束。主算法返回停止时 yₜ。缩写任务附录另述按多方面分数选候选，不能泛化成默认存在一个可靠外部验证器。PDF p.4 · §2 / §3.1PDF p.22 · Appendix H / Table 10

为何会失败：写得出反馈不代表反馈正确

  • 漏检错误：数学推理可“看起来很一致”；文中 ChatGPT 对 94% 实例给出“看起来没问题”的反馈。该数字描述该设置的反馈行为，不是 94% 正确率。
  • 定位或建议错：作者在代码优化/数学的 70 个定性样本（35 成功、35 失败）中，失败子集约 33% 属错定位，61% 属不合适修法，6% 属好反馈未被正确实施；不是全数据集失败率。
  • 越改不一定越好：缩写的多方面目标可此消彼长；轮数增加无单调质量保证，停止指标也可能误判。
  • 模型与范围：Vicuna-13B 不能稳定按格式反馈/遵循改写提示；主结果来自当时闭源模型和英语任务，不能外推到任意模型或语言。

阅读结论：这篇最强的启发是把局部评价变成显式可执行文本，并在推断期复用；最关键的未解问题是反馈质量。原始 Self-Refine 不默认查询外部事实、不证明修订正确，也不保证会发现复杂推理错误。

创新落点与相近方法的边界

贡献归纳：同一模型、显式具体反馈、保留历史的多轮改写，以任务提示实例化到多种生成任务；不是训练新的 critic，也不是只做多次独立采样。本文还比较 k=4 无反馈采样，支持“有方向的修改”不只是多产出几个候选，但不应写成所有预算下更优。PDF p.7 · 1 vs. k 比较

对 Reflexion：本文 Appendix B 将其与 ReAct 环境规划/下一次尝试的反思区别；Self-Refine 的核心状态是当前稿及改写历史。对 CRITIC：补充阅读中，后者用工具反馈支持修订；不能把那种外部核验能力套进 Self-Refine。

    训练模型模拟写作、建议、编辑与解释；说明“反复修改”早已有之，本文变化在于避免另训领域 refiner。简介据官方摘要及本文 §5。

    把任务反馈写进 episodic memory，改进后续尝试。本文 v2 引用的是同期早稿，链接为其同一论文编号后续题名；不混用其后续实验数据。
