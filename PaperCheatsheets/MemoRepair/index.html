来源撤回 → 类型候选/修复前提 → 闭合集选择 → 依序验证发布

拿一个输入走通方法

错源 F 支撑了摘要 A，报告 B 又依赖 A。修复 B 看似收益高，但必须先修 A。

  1. 从 F 沿影响边撤回全部候选后代，先停止旧版服务，而不是一边修一边继续用旧报告。
  2. 为 A、B 各构造可执行候选，明确价值、成本及真正所需的修复前驱；B 的前驱集合含 A。
  3. 例如净权重 pA=−2、pB=5 时，不能只挑 B；若其他条件满足，可闭合地选 {A,B}，总净权重为 3。
  4. 先执行/验证 A，再处理 B；任一必要前驱失败时，其依赖后继不能重新发布。数字只是解释固定 λ 的选择，不是实验结果。

关键设计为什么需要

独立贪心会忽略前驱成本；闭包约束把“有价值”和“能依赖地执行”一起考虑。一次图割精确性只覆盖固定候选与 λ 的选择问题。

术语就地解释

pᵢ=wᵢ−λcᵢ：价值减加权成本；前驱闭合：选中后继时也必须选其所需前驱。

问题与输入输出

  • 问题：源记录更新不等于派生状态更新；旧摘要、缓存、提示技能、工具流程甚至神经技能仍可被取用。
  • 输入：持久产物溯源图 G、失效源 F、事件类型/更正内容/新接口，以及成本权衡 λ。
  • 输出：经验证并重新发布的后继集合；失败、未选中或不再可修的产物继续隐藏。

p.1 · 摘要 / §1

图旁中文对照 / 阅读顺序

  • 左：Influence edge（影响边）决定级联；Semantic edge（语义相似边）仅辅助检索。
  • 中：①定位并撤回→②依产物构造候选→③在价值−成本目标下选可执行的前驱闭合集。
  • 右：按依赖执行→验证→合格才发布；前驱失败时，其依赖后继也不能回到服务。

p.3 · Figure 1

机制顺序｜输入 → 中间产物 → 判断 → 输出

  1. 定位/撤回：仅沿影响边计算 C(F)，包含源；所有 C(F) 立即不可服务，候选修复对象为后代 D(F)=C(F)\F。p.2 · §2.1；p.3
  2. 构造候选：从级联外保留证据、正确替代源和当前接口重建；确定性产物重算，摘要/提示/流程再生，神经技能作参数修复；无支撑则remove。p.3 · §2.3
  3. 记录合同：每个候选含修复算子、可执行标志 vᵢ、价值 wᵢ、成本 cᵢ，以及它真正需要的受影响前驱 Pᵢ；这不同于原始来源边。p.3 · §2.3
  4. 选择：最大化 Σ(wᵢ−λcᵢ)xᵢ，要求 xᵢ≤vᵢ 且选后继必须选其所需前驱；固定候选/λ时，反向大容量边把约束转成一次s–t最小割。p.4 · §2.4 / Theorem 1 / Algorithm 1
  5. 执行/发布：按修复依赖拓扑顺序执行；通过结构、执行/任务等验证后才发布，失败及依赖者继续撤回；原失效版本始终不可见。p.4 · §2.4 / Theorem 1 / Algorithm 1

下面的差异按作者论述归纳；参考前作仅核对官方题名与摘要，未据此宣称已独立证明新颖性。p.9 · §4；p.10–12 References

以前的具体不足 → 本文怎样处理

所指方法 / 不足本文设计 / 作用
MemGPT / A-MEM等记忆管理：组织与检索不自动提供更新后的级联撤回。增加先撤回的可见性屏障，防止修复期间继续读到旧派生物。
只做模型遗忘：参数侧抑制不能自动清掉缓存、摘要和可执行流程。统一处理多种持久产物，按其类型选重算、再生、参数修复或移除。
修全部：可能执行大量收益低的修复；按单点收益贪心又可能漏掉前驱成本。用真正的修复前提构造前驱闭合选择，在固定权衡下精确求解。

p.9 · §4；p.10–12 References

创新差异｜作者主张，按机制归纳

  • 契约：将“隐藏→构造后继→验证→重新发布”定义为受控状态转移。
  • 依赖区别：撤回范围由来源影响边决定；重新发布由修复时的必要前驱决定。
  • 优化归约：把固定λ下的发布选择归约到经典最大闭包；作者明确未提出新图割算法。

p.3 · §2.2–2.4；p.4 Algorithm 1

结果与使用边界

  • 作者报告：相对Repair all恢复91.1–94.3%的已验证发布量，归一化修复算子成本为0.57–0.76；成本不含撤回屏障。
  • 保证条件：完整影响溯源下陈旧暴露为0；漏掉1%影响边时，文中Leak升至17.7%。
  • 边界：验证通过只代表所实现检查覆盖；神经技能不保证精确遗忘。一次最小割精确性限固定候选/固定λ，硬预算版通常更难。
