拿一个输入走通方法

步骤 a 产生错数字，b 仅复制它，c 用它算答案；另有步骤 d 已在后面被明确修正。

  1. 先从任务、角色和工具形成预期 π，再用分层窗口摘要召回偏离预期的候选。
  2. 若 b 只是继承 a 的错误，沿 follow_up 上追；若 c 另引入新的转换错误，可作为 error_shift 候选。已修正的 d 不自动承担最终根因。
  3. 按预期与传播关系取最多 3 个候选，读取各自附近原步骤，判断独立引错、单处改正是否足够及最早性。
  4. 在初选位置 ±2 邻域做赞成/反对比较，必要时改判，再输出 agent 与步骤。

关键设计为什么需要

关系类型用来区分来源、变换、传播和修正；反事实充分性仍是 LLM 读日志作判断，没有在这个流程中执行真实续跑。

术语就地解释

π：不读取中间轨迹时形成的任务预期；follow_up：继承推进；error_shift：新引入或变换错误。

问题与输入输出

  • 问题：下游步骤在错误状态下可能局部合理；逐步独立判错会把载体当根因。
  • 输入：任务Q、智能体及角色/系统提示、可用工具、错误最终答案，以及含推理/动作或消息/观察的失败轨迹τ。
  • 输出：决定性步骤 t̃、责任智能体 α̃，以及归因理由；主要实现与评测围绕单步骤标签。

核验到底做了什么

  • 反事实核验是LLM判断：“只改候选，前序固定、后序允许调整，最终结果能否正确？”
  • 论文提供局部日志与提示词让模型判断，没有执行真实环境重放，也没有输出修复后的运行轨迹。

具体流程｜每一步产生什么、按什么判断

  1. ① 构造π与M：先验π只读任务、角色/工具和错误最终答案，不读中间轨迹；记录预期行为、输出类型、约束与风险。分不重叠窗口建立高层阶段摘要→中层关键决策→低层原始证据；按结果相关、违背π、推理/动作/观察不一致三信号取候选C。p.4 · §2.1；p.5 Table 1
  2. ② 有类型剪枝：给候选间关系标六种类型，保留可能引入/变换错误且影响可达最终答案的节点；继承传播向上追，已修正、无关、无下游用途者可排除，得到C′。p.5 · §2.2；p.6 transition labels
  3. ③ 排名并核验：结合π与依赖路径，保留TopK=3；对每个候选读取i−1、i、i+1原始步骤及关联低层证据，检查“独立引错 / 单处改正足够 / 满足前两项中最早”，得初选t̂。p.6 · §2.3；p.7 §2.4
  4. ④ 局部再搜索：在t̂±2范围逐步给赞成/反对理由，分根因、传播、症状、仅有贡献四角色；对比邻居，保留或改判为t̃及其智能体。p.7 · §2.4

类型判据、差异与选题对照

关键是依赖类型决定如何归因，而非“后一步也错了就再加一个根因”。候选筛选与充分性判断均受LLM可靠性限制。p.5 · §2.2；p.6 transition labels p.9 · §5 Limitations

六类边怎样影响归因（不是一律可达就保留）

关系标签具体含义候选处理
follow_up后步沿用前步输出/假设正常推进可剪；上游已错则将后步视为传播载体，继续回溯。
error_shift后步新引入偏差，或把上游问题变成另一种错误保留为可能错误来源或变换点。
redundancy / no_influence重复而无新证据 / 不消费前步输出剪重复或无关联系；若步骤另有独立偏差则仍保留。
correction / dead_end后步已修正前错 / 输出未供后续或最终答案使用影响在修正处终止或无下游用途时剪枝；独立影响证据可例外。

以前的具体不足 → 本文设计（按作者论述归纳）

所指方法 / 不足FALAT对应设计
单次全文LLM判断：长输入有位置/顺序偏差，早期错误又可能在内部自洽。不读中间轨迹先建π；三层窗口表示先粗后细地定位。
逐步分类/学习式归因：独立评分难以分清错误来源与传播。用六类关系解释决策、数据、消息怎样传递错误，并剪去无影响节点。
归因容易锚定在“看起来合理”的候选。Top3候选核验，再对t̂±2邻居作赞成/反对比较，允许改判。

p.2 · §1–2

贡献差异｜作者主张，按机制归纳

  • 搜索空间：与中间轨迹独立的π + 对齐的高/中/低三层表示。
  • 来源识别：用有类型依赖区分错误引入、变换、传播和修正。
  • 候选核验：三个决定性判据与邻域对比组成可修正的归因过程。

p.2 · Contributions；p.9–10 §6

实验一句与局限

  • 作者报告：Who&When 184条失败轨迹（126算法生成/58手工）；最佳精确步骤准确率46.0%/29.1%，分别来自MiniMax 2.5/DeepSeek V3.2。p.8 · Table 2
  • 边界：多阶段LLM误判可累积；窗口处理可能漏跨窗长依赖；分散且相互作用的多根因超出主要单步骤设置。p.9 · §5 Limitations

最值得记住｜整理者判断

  • “继承错误”与“把错误变成新错误”应给不同类型；只有后者才可能是新的决定性候选。

解读 · p.6 · §2.2–2.4；p.9 §5

选题对照（整理者判断）

  • 与AG-Repair重合：失败轨迹、typed依赖、根因与污染传播区分。尤其值得对照error_shift与follow_up的语义。
  • 修复后旧结果的有效性、隐式依赖发现、checkpoint与非连续后缀复用仍需另建判据和执行验证；FALAT的“反事实充分性”是归因判断，未实现上述修复执行链。

解读 · p.6 · §2.2–2.4；p.9 §5
