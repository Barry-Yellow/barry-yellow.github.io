先录下一次成功执行，原样重放成功前缀，只在指定一步引入错误，再让原 Agent 真实续跑。如果任务因此失败，就得到一条带有已知错误位置、责任 Agent 和错误类型的诊断考题。

最吸引人的点：先造出有对照的失败，再测诊断是否找得准。主要贡献是基准构造与评测，不是一个自动修复算法。

以前的问题 → 本文的改法

  • 人工标注自然失败很贵。一代 Who&When 仅 184 条、以文本任务为主；Pro 用受控构造扩展规模与模态。
  • 重跑后再注入会混入前缀漂移。本文重放成功前缀、恢复工具和环境状态后，再改一处。
  • 只报最终答错，难知道怎么改。本文给出 agent / step / error mode 三元标签，测局部诊断能力。
依据：§1、§3，PDF pp.1,3–5；比较是本文提出的定位。

核心创新，按理解顺序

  1. 受控对照：成功种子作基线，固定此前的行为和观测。
  2. 保持“像这个 Agent 犯的错”：前沿模型生成注入提示，仍由原 Agent 模型在原上下文里生成错误步骤。
  3. 真实后果：只改一次，之后由原系统继续运行；能自救成功的轨迹不入选。
  4. 更广诊断对象：文本 / 图像 / 视频，单 Agent 与多 Agent，统一错误分类和评测。

构造流程：每一步的输入、动作与产物

1. 收集并判分运行各 Agent × benchmark，记录任务、消息、动作、观测与产物；用可用的官方 evaluator 判成功 / 失败。
2. 用自然失败定范围博士级审阅者归纳 6 家族 / 18 类型，并建立每种配置中“哪些错误可能出现、在哪出现”的 profile。
3. 选合法注入点从成功种子按目标类型采样 t；排除执行异常、不适用步骤。规划偏早，验证需已有证据，感知需图像观测。
4. 重放后只改一步重放 a₁…aₜ₋₁；前沿模型生成提示 → 原 Agent 模型产出错误动作 ãₜ。之后恢复原设置自由续跑。
5. 失败与质量过滤只留最终失败；去掉暴露“注入提示”等构造痕迹，过滤注入前答案已过于显著的情况；保存轨迹与标签。

“决定性错误”怎么理解？

论文定义：最早一个在纠正后能把失败变成成功的步骤；多 Agent 情况的责任人就是该步输出的 Agent。

成功种子 τ = (a₁, …, aₜ, …, aT)
失败分支 τ̃ = (a₁, …, aₜ₋₁, ãₜ, bₜ₊₁, …, bM)

aᵢ：记录的成功动作；t：注入位置；ãₜ：唯一注入的错误动作；bᵢ：原系统受到影响后新生成的后续行为，长度也可能改变。标签：(agentₜ, t, mode)。

成功分支提供已知可行的对照。这不是说所有自然失败都只有一个根因，也不是枚举并验证了所有可能的纠正位置。

依据：§3、§3.3，PDF pp.3–5；后一项为解读边界，见附录 A.1。

走通一遍：两张发票求和（教学示例，非原始样本）

任务：发票分别为 20 元和 30 元，求合计。

成功种子

① 采集 Agent：读到 20、30

② 计算 Agent：20 + 30 = 50

③ 汇总 Agent：最终报 50 ✓

→
重放①，只干预②

① 原样得到 20、30

② 注入：20 + 30 = 45

③ 真实续跑后报 45 ✗

标签是 计算 Agent / step 2 / Calculation error。如果汇总 Agent 自行复算并返回 50，则这次注入没有造成最终失败，不收入本基准。

Warm start 的实现要点：不只把聊天记录贴回去

  • 框架级重放：动作仍经过工具解析、代码执行和环境交互，恢复上下文以及环境状态。
  • 静态外部观测：搜索、网页内容、图像等用工具参数的 SHA-256 键查 SQLite 缓存，重用种子观测。
  • 网页摘要的例外：附录说明只缓存 raw page，不缓存二次 LLM 摘要；“字节一致”不能扩张到所有模型生成的中间文本。
  • 有状态浏览器：用原生控制器重放导航、点击、输入和代码。发现重放异常或失配就中止，换位置重试或记为未尝试。
依据：§3.3（p.5）、附录 G.3（pp.27–28）。这些措施降低漂移；论文没有证明任意隐藏环境状态都被完全恢复。

读者应该保留的边界

  • 单一可定位错误是设计选择。每条只有一个标签；真实系统可以多错交互、相互补救或共同致败。论文附录明确承认这一限制。
  • 构造因果对照 ≠ 自然失败唯一根因证明。成功种子和受控失败分支提供已知对照；没有穷举全部替代动作、随机续跑和隐藏状态。
  • 重放的可信度依赖缓存和保真检查。动态网页、二次摘要、未观测状态仍需具体实现核验，不能把宣传中的“严格”当作任意环境的形式证明。
  • 分类不是穷尽的。18 类来自本文任务集合；新领域可能需要新增类型，细类相邻边界也会引发人 / 模型分歧。
  • 有答案不总是更会诊断。它可能帮助核对感知，也可能诱导只比最终答案。论文展示的是按错误类型 / 场景变化的现象。
  • 诊断价值和修复收益要分开测。本文测试定位与分类，并未由这些主结果证明自动修复后能提高多少任务成功率。

记住这条主线：自然失败提供“可能犯什么错” → 成功种子提供“原本可以做好”的对照 → 重放 / 注入 / 真实续跑构造已知错误 → 用 who、when、error 检验诊断能力。
