AgentAsk：多智能体要学会主动提问

AgentAsk: Multi-Agent Systems Need to Ask

作者：Bohan Lin、Kuo Yang、Zelin Tan 等
机构：中国科学技术大学、上海人工智能实验室、西安交通大学、新加坡国立大学
版本：ACL 2026 Long Papers 正式论文；PDF 第 28055–28077 页

核心思路
在智能体间的每次信息交接处放一个轻量澄清员，判断是否要问、问谁、问什么；在错误传给下游之前补齐或纠正信息。

问题｜局部错误怎样变成系统失败？

上游交来缺条件、错数据或含糊指代；下游直接采用并继续推理，后续结果就可能层层受影响。最终答案错了，根源可能藏在早期交接。

方案｜在“边”上放一个澄清员

把两名智能体间的一条消息交接看作一条边。澄清员读取当前消息与局部上下文，只在需要时提问，带着澄清内容继续执行，不改变原有团队编排。

输入、决策、输出

环节具体内容
输入任务、当前交接消息及局部上下文 xₜ。
决策zₜ：是否发问；ṽₜ：向谁问；qₜ：问题内容。
输出不问则放行；要问则取得回答、更新交接内容，再继续。

aₜ=(zₜ,ṽₜ,qₜ) 是一次交接的控制动作；B 是澄清预算。§4.1 / PDF p.4。

四类边级故障：发现了什么，应该问什么？

① 信息缺失 Data Gap
漏掉约束、输入或单位；追问缺失字段。
② 信号污染 Signal Corruption
错值或错误结构被当作事实；要求核实结果。
③ 指代漂移 Referential Drift
“它”、变量名或对象在交接中指向不明；确认对象与值。
④ 能力错配 Capability Gap
任务交给不擅长的角色；请求更合适的角色或指导。

怎么训练？效果能说明什么？

Demonstration → E-GRPO → online clarification
记住区别：训练时用示范和结果奖励学习提问策略；使用时只在交接处判断并发问。它不是失败后重放整段轨迹的修复方法。

从输入到输出：训练与推理分开

阶段输入 → 处理 → 产物
① 示范学习交接上下文与强模型示范 → 学习“是否问、问谁、问什么” → 得到初始澄清策略。损失同时覆盖决策和问题内容。
② 强化学习任务执行轨迹 → 局部奖励衡量澄清有效、提问频率与格式；再引入最终任务结果 → E-GRPO 优化策略。
③ 在线推理某次交接及局部状态 → 决定放行或向角色询问 → 回答与更新后的交接进入后续执行。

§4.1–4.3，Eq.1–8 / PDF p.4–6。有效提问、少问和格式奖励是局部信号；最终正确性是全局信号。

原文案例｜补上空字符串边界

任务：写生成最短回文的函数。上游方案直接读取字符串首尾，并假设输入非空；空字符串会产生索引错误。

AgentAsk 问编程角色：是否应明确空字符串行为，并在读取首字符前检查长度？
更新后的交接：长度为 0 返回空串；长度为 1 可直接返回；其余情况再做后续处理。

消融：MasRouter + MBPP 中，完整模块 83.55%，移除澄清有效性奖励后 80.05%；仅说明该设置下该组件有帮助。Table 3 / PDF p.8

限制：问题必须能在交接处通过可用角色澄清；模型内部幻觉未必可解决。本文没有证明已生成的下游状态可安全复用，也没有选择性回放。

与 AG-Repair：AgentAsk 偏运行中预防传播；AG-Repair 关注失败后干预与下游复用，两者关注时机不同。§4、Limitations；关联为整理者判断。
