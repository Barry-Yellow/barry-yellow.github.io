论文速查 · 故障归因与多智能体修复

AgentAsk｜在智能体交接处及时澄清

AgentAsk: Multi-Agent Systems Need to Ask
Bohan Lin、Kuo Yang、Zelin Tan 等；中国科学技术大学、上海人工智能实验室、西安交通大学、新加坡国立大学。
ACL 2026 Long Papers，2026 年 7 月；使用 ACL Anthology 正式 PDF。论文官方页面 · 本地原文 PDF

一句话：在两个智能体交接信息时，增加一个“澄清员”：先判断交接是否有风险；需要时向合适的人提出简短问题，让错误在进入后续步骤前被纠正。它处理的是运行中的交接，不是对已完成轨迹做选择性回放。

1｜问题：信息交接为什么会出错？

一个多智能体任务中，上游智能体将文字或中间结果交给下游；后者往往会把这份结果当成事实继续计算。一个遗漏、错数或含糊指代，可能被后续角色不断放大。作者审阅 824 条执行日志，以智能体间消息为分析单位，归纳四类交接问题（§3、Fig.2；该统计是作者样本内分布）：

类型具体例子适合问什么
Data Gap 信息缺失计算要求转换单位，但上游没说明单位。“这里的数字是毫升还是升？”
Signal Corruption 信号污染传下来的换算结果本身算错。“请检查这一步换算是否正确。”
Referential Drift 指代漂移“它”可能指产品 A 或产品 B。“这里的它指哪一项？”
Capability Gap 能力错配交给缺少相应能力的角色处理。“是否应请具备数学能力的角色计算？”

以上表中例子是为理解机制自行构造，并非论文原案例。

2｜方法：在交接的边上决定何时、问谁、问什么

上游消息 + 局部上下文 → 判断是否询问 → 选择被问角色 → 生成简短问题 → 获得澄清 → 下游继续执行

输入与输出：每次交接时，澄清员读当前交接消息与局部状态 x；输出三个动作：是否询问 z、被询问角色 v、问题 q。z=0 时直接通过；z=1 时发问，结合回答继续任务。并不是每条消息都重新生成。（§4.1、附录 A.1）

自拟例子：上游说“成本是 30，换算后请统计”，却没写币种。澄清员识别为信息缺失，问上游“30 是美元还是人民币？”；对方补充“美元”后，接收方基于补充信息继续。这个例子只说明流程，不代表一次已复现的运行。

3｜如何学会少问、问对？训练与运行分开

  1. 示范学习（SFT）：用强模型生成交接示例，学习“要不要问、问谁、怎么问”。训练损失包含决策和条件提问两部分。（§4.2）
  2. 强化学习（E-GRPO）：用局部奖励衡量澄清是否消除不确定、是否提问过多和格式是否合规；再结合最终任务正确与否，让局部提问有全局目标。作者通过滑动窗口惩罚频繁提问。（§4.3，式 3–8）
  3. 在线执行：将训练后的轻量模块放进智能体交接处，按当前上下文决定是否介入。结果依赖任务、角色和上游能否回答，不保证每次澄清都能修复。（§4、§6）

这种设计与事后调试的差别：DoVer 在失败发生后提出干预并重放；AgentAsk 尝试在错误传递前发现并澄清。两者处理的时机和可获取的信息不同。

5｜边界与对 AG-Repair 的启发

  • 纠正发生在交接之前；如果错误已经改变了下游状态，本文没有给出下游结果是否仍可复用的选择性重放机制。
  • 澄清能否成功取决于能否问到能解决问题的角色；作者指出智能体内部幻觉等问题无法仅凭模块完全解决（Limitations）。
  • 可参考其四类边级错误来设计故障类型；不应把“定位到交接边”直接等同于已验证的因果依赖或可复用边界。
