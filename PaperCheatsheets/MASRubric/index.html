MASRubric

利用失败蒸馏的易错准则，审核多智能体系统的信息流

MASRubric: Auditing Information Flow in Multi-Agent Systems with Failure-Distilled Pitfall Rubrics

Yutong Wang, Siyuan Xiong, Xuebo Liu, Wenkang Zhou, Liang Ding, Miao Zhang, Min Zhang
arXiv:2602.23258v3 · 2026-09-28

一句话读懂

离线把失败轨迹蒸馏成可复用准则库，在线按情境选择准则、逐条核验；消息只有达标才传播，失败则返修或拦截。

p.4 · Fig.2 · §3.2

原架构图｜下部建库，上部检索、判断、干预

原图：离线 miner 从失败 Agent 输出挖准则并去重；在线 auditor 在消息广播前运行。反馈交回原 Agent，而不是由 auditor 直接替它作答。p.4 · Fig.2 · §3.2

问题｜错误进入下游知识库就会继续扩散

  • 默认传输：上游输出不经筛查便加入下游动态知识库 Kj。
  • 缺少标准：测试时的中间消息没有专门参考答案；自检也可能继承原模型的错误。
  • 准则方向：写出容易犯的错、出现条件和具体检查，而不是泛泛要求“逻辑正确”。

p.3 · §3.1 · Eq.2

方案｜从生成答案，转到控制信息传播

  • 粗检索：任务场景与动作类型 → embedding → top-Kcand 候选。p.5 · §3.3 · Eq.4–5
  • 细筛选：auditor 结合输入、角色与输出，选最多 Kctx 个准则。p.5 · §3.3 · Eq.4–5
  • 逐条审：只按每条准则的适用条件与检查指令判断，给违例标记与理由。p.5 · §3.3 · Eq.4–5
  • 三态控制：Pass 放行；Revise 返修；Withhold 不广播。p.5 · §3.3 · Eq.4–5
  • 准则 C=(n,d,a,s)：名称、根因、适用条件、检查指令；离线建库，在线固定。p.3 · §3.1 · Eq.2

离线与在线｜参考答案出现在哪里

  • 离线：源任务有 Y*；只有 MAS 最终回答失败的轨迹进入挖掘。
  • 按角色检查：某 Agent 在其职责内没错，就不必贡献准则。
  • 在线：审核中间消息不依赖它的参考答案；reference-free 仅指这一层。

p.4 · §3.2

实际运行模型｜各司其职

  • 推理 / 审核：Qwen3-8B，关闭 thinking。
  • 选择器 / 嵌入：Qwen3.5-9B / Qwen3-Embedding-8B。
  • 离线挖掘 / 去重：GPT-5.4 / GPT-4.1-mini；在线不重新建库。

机制｜四字段如何变成一个传输闸门

检索负责“此时可能犯哪种错”，逐条判断负责“这条消息是否犯错”；满意率把局部判断转成实际信息流决策。p.5 · §3.3 · Eq.4–5

原准则 Fig.7｜保险覆盖百分比理解错误

原图：先确认总费用，再按覆盖比例计算；Name、Definition、Applicability、Directive 在下表给出中文与用途。p.20 · Fig.7

四字段｜不要把检索键与审计输入混为一谈

字段中文 / 作用
n / Name失败模式名称
d / Definition诊断根因，参与去重和筛选
a / Applicability何时适用，是在线检索的匹配对象
s / Directive具体查什么；审计时提供 a+s

p.3 · §3.1 · Eq.2

① 从失败轨迹挖库

  • 源数据：任务 Q 与参考答案 Y*；运行 MAS 后筛出最终回答错误的轨迹。
  • 挖掘粒度：逐个 Agent，结合角色 Ri 与输出 oi 判断；正确的 Agent 不强行挖错。
  • 候选：每个 Agent 的准则数由 miner 决定，允许为 0。

p.4 · §3.2

两阶段去重

vnew = Memb(dnew ⊕ anew)
p.4 · §3.2
  • 先检索最相似的 20 个旧准则，再由 dedup LLM 判断是不是新错误模式。
  • 这一步避免近重复准则挤占在线有限检查槽位。

p.4 · §3.2

② 先粗召回，再细筛选

  • Query：auditor 提取任务场景与动作类型，编码成查询向量。
  • Top-Kcand：语义匹配准则的 applicability，先取 20 条。
  • Bctx：再看 Agent 输入、角色和当前输出，筛到最多数学 5 条、代码 3 条。
  • 每条消息、每轮返修都重新选择适用准则；不是一套清单固定扫所有消息。

p.5 · §3.3 · Eq.4–5

参数｜数学 / 代码

  • τpass：60% / 100%；Tmax：均为 3。
  • Auditor 温度 0；其他模型默认 0.7。

p.6 · §4.1 · Hyper-Parameters

③ 逐条判断并聚合

p = 1 − Σ vₖ / |Bctx|
p.5 · §3.3 · Eq.4–5
  • vₖ=1 表示违反第 k 条准则；vₖ=0 表示满足。
  • auditor 对每条返回违例标记与诊断理由 rₖ。
  • 只用适用条件 a 与检查指令 s 判断，避免把准则名字当结论。

p.5 · §3.3 · Eq.4–5

审核标准｜不是挑风格

  • 只判会影响最终结果的致命逻辑/编码错误。
  • 要能给具体公式、步骤、代码行或参数纠正；措辞不完美、低效或风格问题不算。

p.21 · Fig.9 / Fig.10 p.22

④ Pass / Revise / Withhold

  • Pass：p≥τpass，接受当前版本并广播给后继 Agent。
  • Revise：p<τpass 且仍有预算，把违例理由反馈给原推理 Agent，生成新版本。
  • Withhold：3 轮预算耗尽仍不达标，置输出为空，不更新下游知识库。
  • 知识库更新只发生在放行之后：Kj 加入角色与输出这对记录。

p.5 · §3.3 · Eq.4–5

具体案例｜第一轮也可能没修好

  • 正九边形外扩：初答 18+7π；第一次返修仍同错。
  • 第二次指出应使用外角 2π/9 而非内角 7π/9，改为 18+2π，并满足所选 5 条准则。

核心思路

从历史失败中提炼“容易在哪种情境下犯什么错、该怎么检查”的准则；新消息广播前检索适用准则，再决定放行、返修或扣留。

以前文章的问题 → 本文如何解决

已有做法与具体不足本文的对应设计
Self-Refine 主要依赖模型自我判断，检查标准不显式使用从失败中提炼的可检查准则。
人工统一清单难覆盖每一步，依赖参考答案的 rubric 又难用于未知输入离线挖库，在线按情境检索；测试时不需要标准答案。
只给分数不能阻止错误传播分数直接控制广播、返修与扣留。

依据本文引言、相关工作及方法压缩整理；对照仅针对列出的做法。

创新点｜具体改了什么

  • 把“正确答案应包含什么”换成“这类推理容易犯什么错”。
  • 检索键是适用条件，审计反馈作用于消息传输，而不只评价最终答案。
最吸引人的点 （整理者判断）

错误经验被做成可复用的“消息闸门”，在下游把错话当证据之前介入。

创新点为贡献归纳，不作未经全面核验的首次声明；亮点为整理者判断。

    由同一 LLM 生成反馈并迭代修改输出，无需额外训练。 对照其反馈—修订循环，理解本文新增了哪些证据或控制。

    不更新权重，把一次失败和反馈压缩为下一次能执行的语言经验，并用有限记忆影响后续尝试。 对照跨试次反思记忆，理解本文的修复/审计差异。

    原文引用 · 简介据本文介绍/已核实摘要
