# 蚁智投研智能体平台需求文档

## 1. 背景

蚁智定位为蚂蚁财富事业群内部的投研智能体与能力中台，服务对象不是外部普通投资者，而是内部投研投顾人员、财富业务团队、C 端产品技术团队，以及需要接入投研中台能力的垂类业务团队。

蚁智的核心价值是把投研技术组沉淀的数据接口、信息分析、事件分析、报告生成、内容理解、投顾辅助等能力，封装成可复用的工具、技能和智能体能力，降低投研投顾团队和业务团队的使用门槛。

## 2. 业务定位

蚁智不是基金发行平台，也不是直接面向所有支付宝用户的大众投顾入口。它是投研投顾技术部面向内部和业务侧的 AI 能力平台。

核心定位：

- 面向投研投顾同学：提供会议整理、资料处理、报告撰写、模型辅助、资讯分析等工作台能力。
- 面向财富 C 端业务团队：提供可下载、可调用、可集成的投研中台能力，例如事件分析、行情解读、基金分析、资讯摘要、数据查询。
- 面向技术接入方：通过 skill、MCP、API、数据接口等方式，把投研能力接入支付宝 C 端业务、余额宝、稳健团队、帮你投、蚂小财等业务系统。

一句话：蚁智是投研能力的生产、封装、分发和接入平台。

## 3. 用户分层

| 用户类型 | 代表用户 | 使用场景 | 交付形态 |
|----------|----------|----------|----------|
| 投研投顾人员 | 基金研究员、投顾、投研运营 | 开会、整理资料、写报告、做产品分析、生成投顾话术 | 投研工作台、模型编排、报告生成工具 |
| 内部 AI 使用者 | 使用 Mind、本地小龙虾、集团 Homi 的员工 | 安装技能、调用工具、个性化配置智能体 | skill、插件、MCP 工具 |
| C 端业务团队 | 支付宝财富、余额宝、稳健团队、帮你投、蚂小财 | 将投研能力嵌入业务流程，例如热点 push、行情解读、基金分析 | skill 下载、MCP 接入、数据接口、服务化 API |
| 平台运营/中台团队 | 投研技术组、能力运营方 | 管理平台技能、审核外源技能、维护能力目录 | 技能市场、权限管理、版本管理、审计系统 |

## 4. 核心业务流程

```text
投研能力沉淀 -> 工具/模型/模板封装 -> skill 化 -> 平台发布 -> 用户安装/调用 -> 业务系统接入 -> 使用反馈 -> 能力迭代
```

其中 skill 是能力分发的核心载体。平台不只是提供一个聊天入口，而是把可复用的投研能力标准化、产品化、可治理化。

## 5. 主要功能模块

### 5.1 投研工作台

投研工作台服务内部投研投顾同学，核心目标是提升投研内容生产效率。

主要能力：

- 会议纪要整理：根据录音、会议文本、调研纪要生成结构化摘要。
- 资料归纳：对公告、研报、财报、资讯、访谈材料进行要点提取。
- 报告生成：基于多个模型输出不同质量、不同角度的内容，再由用户拼接成正式文章。
- 模型对比：同一任务调用多个模型，比较结论质量、表达质量、事实一致性。
- 模板化写作：支持点评报告、跟踪报告、基金分析、事件分析、市场解读等模板。

### 5.2 投研能力中台

中台能力面向内部业务团队，不直接面向外部大众用户。

主要能力：

- 数据接口：基金数据、市场数据、行情数据、持仓数据、风险指标、用户行为数据。
- 信息接口：新闻资讯、公告、政策、研报、舆情、事件标签。
- 分析能力：事件分析、基金诊断、组合分析、资产配置、热点解读、风险提示。
- 内容能力：用户易懂版解读、投顾话术、push 文案、产品说明、风险提示文案。
- 接入能力：skill 下载、MCP 调用、API 服务、工具插件。

### 5.3 Skill 能力市场

skill 是蚁智能力分发的核心形态。它把数据接口、分析逻辑、提示词模板、模型调用、工具链和输出格式封装成一个可安装、可调用、可治理的能力单元。

skill 需要支持两类：平台技能和用户技能。

## 6. Skill 体系详细需求

### 6.1 Skill 分类

| 类型 | 定义 | 权限 | 典型来源 | 使用方式 |
|------|------|------|----------|----------|
| 平台技能 | 投研技术组沉淀的标准能力，经过审核和维护 | 用户只能使用，不能修改 | 平台内置、官方维护 | 搜索、安装、调用、业务接入 |
| 用户技能 | 用户自定义或外部导入的个人技能 | 用户可创建、编辑、删除 | 对话生成、zip 上传、GitHub 链接安装、本地导入 | 个人使用或按权限共享 |

平台技能强调稳定性、合规性、复用性。用户技能强调灵活性、个性化和探索性。

### 6.2 Skill 来源

skill 来源需要覆盖以下路径：

- 对话创建：用户在对话中描述需求，由系统生成技能草稿。
- 平台内置：投研技术组沉淀的标准工具和模板。
- zip 上传：用户从外部下载技能包后上传安装。
- GitHub 安装：通过开源仓库链接安装技能。
- 本地导入：从本地小龙虾、集团 Homi 等环境迁移或安装。
- MCP 工具映射：将已有 MCP server 或工具能力包装成 skill。

### 6.3 Skill 基本结构

每个 skill 至少包含以下元信息：

| 字段 | 说明 |
|------|------|
| skill_id | 技能唯一标识 |
| name | 技能名称 |
| description | 技能用途描述 |
| owner | 创建者或维护团队 |
| source | 平台内置、用户创建、zip、GitHub、MCP 等 |
| version | 版本号 |
| permission | 可见范围、调用权限、编辑权限 |
| input_schema | 输入字段和参数规范 |
| output_schema | 输出结构和格式要求 |
| dependencies | 依赖的数据接口、模型、工具、MCP server |
| risk_level | 风险等级 |
| compliance_status | 合规审核状态 |
| audit_log | 安装、修改、调用、异常日志 |

### 6.4 Skill 运行链路

```text
用户选择 skill -> 填写输入参数 -> 权限校验 -> 调用数据/工具/模型 -> 生成结构化结果 -> 记录日志 -> 返回结果 -> 收集反馈
```

如果 skill 被 C 端业务系统接入，链路变为：

```text
业务系统请求 -> MCP/API 网关 -> 权限和流量控制 -> skill 执行 -> 结果结构化返回 -> 业务侧二次加工 -> 面向外部用户展示
```

### 6.5 Skill 典型场景

| 场景 | Skill 能力 | 使用方 |
|------|------------|--------|
| 热点 push | 输入新闻事件，输出影响资产、影响行业、风险提示、用户易懂文案 | 支付宝财富 C 端产品团队 |
| 基金分析 | 输入基金代码，输出业绩、回撤、持仓、基金经理、适配人群 | 投顾、基金分析团队 |
| 事件分析 | 输入公告或新闻，判断对公司收入、利润、估值、股价的影响 | 投研、C 端业务团队 |
| 市场周报 | 聚合行情、政策、行业轮动，生成周报初稿 | 投研投顾团队 |
| 组合诊断 | 输入用户组合或产品组合，输出风险暴露、回撤、相关性、再平衡建议 | 帮你投、投顾团队 |
| 投顾话术 | 将专业结论转成面向用户的通俗表达 | 投顾、蚂小财 |

### 6.6 外源 Skill 风险

外源技能包括 zip 上传、GitHub 安装、本地导入等，风险高于平台技能。

主要风险：

- 数据安全风险：外源 skill 可能读取或上传敏感数据。
- 工具调用风险：可能调用未经授权的 API、MCP、外部服务。
- 内容合规风险：可能生成不符合金融合规要求的投资建议。
- 依赖污染风险：外部依赖包可能包含恶意代码或不稳定版本。
- 结果质量风险：提示词、模型调用、数据口径不可控，可能输出错误结论。

治理要求：

- 安装前进行来源识别和风险提示。
- 对 GitHub、zip、外部依赖做安全扫描。
- 对高风险权限进行二次确认。
- 默认禁止访问敏感用户数据和核心生产接口。
- 外源技能必须在沙箱环境运行。
- 调用金融推荐类能力时必须经过合规策略拦截。
- 所有调用记录必须可追踪、可审计、可回放。

### 6.7 Skill 权限模型

| 权限项 | 说明 |
|--------|------|
| 可见权限 | 谁能看到该 skill |
| 安装权限 | 谁能安装该 skill |
| 调用权限 | 谁能执行该 skill |
| 编辑权限 | 谁能修改 skill 内容 |
| 分享权限 | 是否允许分享给团队或组织 |
| 数据权限 | 可访问哪些数据源 |
| 工具权限 | 可调用哪些工具、API、MCP server |
| 发布权限 | 是否允许发布到平台技能市场 |

平台技能默认只读。用户技能默认个人可编辑，团队共享需要审批。涉及金融建议、用户画像、资产配置、风险测评的数据权限必须严格控制。

### 6.8 Skill 审核与发布

平台技能发布流程：

```text
能力提交 -> 元信息补全 -> 安全扫描 -> 合规审核 -> 测试验证 -> 灰度发布 -> 正式上架 -> 监控反馈 -> 版本迭代
```

用户技能发布到团队或平台前，需要检查：

- 是否调用敏感数据。
- 是否输出投资建议。
- 是否有明确输入输出 schema。
- 是否依赖外部不可信服务。
- 是否存在越权调用。
- 是否有版本和回滚机制。

### 6.9 Skill 安装需求

用户安装 skill 时需要支持：

- 平台技能一键安装。
- zip 上传安装。
- GitHub 链接安装。
- 从对话生成后保存为 skill。
- 从 MCP 工具导入为 skill。
- 安装前展示权限清单和风险等级。
- 安装后进入“我的技能”列表。
- 支持启用、禁用、卸载、升级、回滚。

安装流程：

```text
选择来源 -> 解析 skill 包 -> 展示元信息 -> 安全扫描 -> 权限确认 -> 安装 -> 初始化配置 -> 试运行 -> 加入我的技能
```

### 6.10 Skill 与 MCP 接入

MCP 适合把中台能力暴露给业务系统或 AI 工具环境。skill 和 MCP 的关系可以是双向的：

- skill 调用 MCP：skill 内部依赖 MCP server 提供的数据、工具或服务。
- MCP 暴露 skill：把某个 skill 包装成 MCP tool，供外部 AI 环境调用。

典型链路：

```text
业务方 AI 应用 -> MCP Client -> 蚁智 MCP Server -> 权限校验 -> skill 执行 -> 返回结构化结果
```

MCP 接入需要明确：

- tool name 和描述。
- 输入 schema。
- 输出 schema。
- 认证方式。
- 调用频率限制。
- 数据权限。
- 审计日志。
- 错误码和降级策略。

## 7. 投研相关核心能力需求

### 7.1 事件分析能力

输入：新闻、公告、政策、舆情、研报片段、公司名称、基金代码。

输出：

- 事件摘要。
- 影响对象。
- 影响方向。
- 影响业务线。
- 对收入、成本、利润、估值、股价的影响路径。
- 短期情绪影响和长期基本面影响区分。
- 置信度。
- 后续验证指标。

### 7.2 基金分析能力

输入：基金代码或基金名称。

输出：

- 历史收益和回撤。
- 风险收益特征。
- 基金经理风格。
- 持仓行业和风格暴露。
- 同类排名。
- 适配用户类型。
- 风险提示。

### 7.3 资产配置能力

输入：用户风险等级、投资期限、流动性需求、市场观点、资产池。

输出：

- 股、债、商品、现金配置比例。
- 风险收益测算。
- 极端情景压力测试。
- 再平衡建议。
- 用户可理解解释。

### 7.4 内容生成能力

输入：专业投研结论、市场数据、用户场景。

输出：

- 投研版分析。
- 投顾话术版。
- C 端用户易懂版。
- push 文案版。
- 风险提示版。

## 8. 非功能需求

| 需求 | 要求 |
|------|------|
| 安全 | 外源 skill 沙箱运行，敏感数据默认不可访问 |
| 合规 | 投资建议、基金推荐、风险提示必须经过合规策略校验 |
| 可审计 | skill 安装、修改、调用、输出必须有日志 |
| 可回滚 | 平台技能和团队共享技能必须支持版本回滚 |
| 可观测 | 监控调用量、失败率、耗时、用户反馈、异常输出 |
| 可扩展 | 支持新增数据源、模型、MCP server、业务接入方 |
| 可控成本 | 对高成本模型调用设置限流和预算控制 |

## 9. 成功指标

| 指标 | 说明 |
|------|------|
| 投研效率 | 会议纪要、资料整理、报告初稿生成耗时下降 |
| 能力复用 | 平台 skill 被多少团队安装和调用 |
| 业务接入 | C 端业务团队通过 MCP/API 接入的能力数量 |
| 内容质量 | 用户采纳率、人工修改率、事实错误率 |
| 风险控制 | 外源 skill 安全事件数、违规输出数、越权调用数 |
| 用户满意度 | 投研投顾同学和业务团队反馈评分 |

## 10. 一句话总结

蚁智的目标不是做一个普通聊天机器人，而是把投研投顾技术部沉淀的数据、工具、模型、模板和分析能力封装成可安装、可调用、可治理、可接入的 skill 和 MCP 能力，服务内部投研投顾人员和财富 C 端业务团队。
